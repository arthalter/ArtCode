# `artcode/tools/policy.py` 阅读指南

## 一、这个文件是做什么的

`AllowedPathPolicy` 负责限制文件工具只能访问配置允许的目录。

它解决的问题是：

> 即使模型请求读取 `/etc/passwd` 或写入项目外文件，工具也必须在真正操作前拒绝。

它是路径边界，不是完整的 ch06 权限系统。

## 二、路径边界和用户审批的区别

路径边界回答：

> 这个目标是否位于允许目录内？

用户审批回答：

> 即使目标在允许目录内，本次操作是否得到用户授权？

例如：

- 写 `/etc/demo.txt`：越过路径硬边界，应直接拒绝。
- 写 `实验场/demo.txt`：路径合法，但仍可能需要用户确认。
- 读 `实验场/demo.txt`：通常可以自动允许，也可以由更严格策略要求确认。

这两层不能互相替代。

## 三、初始化和路径标准化

```python
@dataclass(frozen=True)
class AllowedPathPolicy:
    allowed_roots: tuple[Path, ...]
```

`allowed_roots` 是允许目录元组。

对象创建后，`__post_init__` 会立即运行。

### 为什么已经有 `__init__` 还需要 `__post_init__`

`@dataclass` 自动生成 `__init__`。如果还要在初始化后校验或转换字段，就放在 `__post_init__`。

代码会：

1. 拒绝空的允许目录。
2. 对每个目录展开 `~`。
3. 转换为解析后的绝对路径。
4. 把标准化结果放回对象。

## 四、冻结对象为什么还能修改

类使用了 `frozen=True`，普通赋值会被禁止。但初始化后处理使用：

```python
object.__setattr__(self, "allowed_roots", normalized)
```

这是 dataclass 冻结对象中的特殊底层写法，用于完成初始化阶段的标准化。

读代码时只需理解：对象最终保存的是标准化后的路径，之后不能随意修改。

## 五、`resolve_existing_path`

用于处理应该已经存在的路径，例如读取文件或编辑现有文件。

流程：

```text
原始字符串
→ 相对路径转为基于 base_dir 的路径
→ 展开 ~
→ resolve 成标准绝对路径
→ 检查是否位于允许目录
```

`Path.resolve()` 很重要，因为路径可能包含：

- `.`：当前目录。
- `..`：上级目录。
- 符号链接。

如果只做字符串前缀比较，攻击者可能用 `../` 绕过边界。

## 六、`resolve_new_file_path`

新文件本身还不存在，因此代码先解析它的父目录：

```python
parent = path.parent.expanduser().resolve()
```

然后确认父目录在允许范围内，最后返回：

```python
parent / path.name
```

### 语法：`/` 拼接路径

`pathlib.Path` 重载了 `/` 运算符：

```python
Path("/tmp") / "demo.py"
```

结果是 `/tmp/demo.py`。

这不是数学除法，而是 Path 对象定义的路径拼接行为。

## 七、`ensure_allowed` 和 `is_allowed`

### `is_allowed`

只回答真或假：

```python
return any(
    resolved == root or root in resolved.parents
    for root in self.allowed_roots
)
```

允许两种情况：

- 目标正好就是允许根目录。
- 目标的父目录链中包含允许根目录。

### 语法：`any`

只要一组条件中有一个为真，`any(...)` 就返回 `True`。

### 语法：生成器表达式

```python
(条件 for root in self.allowed_roots)
```

表示对每个允许根目录计算一次条件。

### `ensure_allowed`

调用 `is_allowed`。如果不允许就抛出 `ValueError`，允许则返回标准路径。

一个适合“询问”，另一个适合“强制保证”：

- `is_allowed`：这个路径允许吗？
- `ensure_allowed`：必须允许，否则立即报错。

## 八、相对路径如何处理

`_raw_to_path` 先检查输入：

- 必须是字符串。
- 去掉首尾空白后不能是空字符串。

如果是绝对路径，直接返回。

如果是相对路径，则基于：

1. 调用方提供的 `base_dir`，或者
2. 第一个允许目录

进行拼接。

### 语法：`base_dir or self.allowed_roots[0]`

如果 `base_dir` 有值就用它，否则使用第一个允许目录。

## 九、为什么这不是沙箱

这个类只检查路径。它不能完全限制 Shell 命令的所有行为。

即使命令的工作目录在允许目录内，Shell 命令仍可能：

- 访问网络。
- 读取环境变量。
- 使用绝对路径访问其他位置。
- 启动其他程序。

因此“允许目录”是重要安全边界，但不能宣传成完整操作系统沙箱。ch06 的审批策略也只能降低误操作风险，不能自动变成强沙箱。

## 十、ch06 与这个文件的关系

建议继续把路径越界视为硬拒绝，不允许用户通过一次确认绕过。

权限判断顺序可以理解为：

```text
参数和路径是否合法？
  ├─ 否：直接拒绝
  └─ 是：继续进行权限策略判断
           ├─ 自动允许
           ├─ 询问用户
           └─ 规则拒绝
```

这样能区分“系统绝不允许的边界”和“用户可以决定的风险”。

## 十一、阅读练习

假设允许目录是：

```text
/project/playground
```

判断以下路径：

- `/project/playground/a.py`：允许。
- `/project/playground/sub/b.py`：允许。
- `/project/playground2/a.py`：不允许。
- `/project/playground/../secret.txt`：解析后在 `/project`，不允许。

尤其注意第三个例子：它虽然字符串前缀相似，但并不是允许目录的子路径。
