# `artcode/agent/tools.py` 阅读指南

## 一、这个文件是做什么的

这个文件是工具调度中心，负责三个问题：

1. 模型请求的工具是否合法？
2. 多个工具应该怎样分批？
3. 每个工具怎样准备并执行？

它不负责工具的具体业务。例如读取文件的代码不在这里，这里只负责找到读取工具并调用它。

## 二、代码结构

文件分成五块：

1. `ToolSafety`：工具安全类别。
2. 工具名称集合：哪些只读，哪些有副作用。
3. 执行批次、计划和阻断结果的数据结构。
4. `ToolBatchExecutor`：计划与执行核心。
5. `classify_tool`：工具分类辅助函数。

## 三、`StrEnum`：带字符串值的枚举

```python
class ToolSafety(StrEnum):
    READ_ONLY = "read_only"
    SIDE_EFFECT = "side_effect"
```

枚举表示“只能从几个固定选项里选择一个”。

相比到处直接写 `"read_only"`，枚举能减少拼写错误，也让可选范围更明确。

## 四、`frozenset`：不可修改的集合

```python
READ_ONLY_TOOLS = frozenset({
    "read_file",
    "find_files",
    "search_text",
})
```

集合适合快速判断某个名称是否存在。`frozenset` 创建后不能修改，适合保存固定规则。

当前分类是：

- 只读：读文件、找文件、搜文本。
- 有副作用：写文件、改文件、执行命令。

`run_command` 永远被视为有副作用，即使命令看起来只是查看信息。这是一种保守且容易解释的分类策略。

## 五、执行批次和执行计划

### `ToolExecutionBatch`

代表一批可以按照同一种方式执行的调用：

- `index`：第几批。
- `safety`：只读还是有副作用。
- `tool_calls`：本批包含的调用。

### `ToolExecutionPlan`

保存多个批次。

例如模型依次请求：

```text
read_file A
search_text B
write_file C
read_file D
```

会被整理成：

```text
第 1 批：read_file A + search_text B，并发
第 2 批：write_file C，串行
第 3 批：read_file D，并发批次
```

### 语法：`tuple[ToolCall, ...]`

表示一个包含若干 `ToolCall` 的元组。`...` 表示数量不固定，但每一项都是同一种类型。

元组创建后不能增删，适合表示已经确定的执行计划。

## 六、`build_plan`：先验证，再分批

这个方法的返回类型是：

```python
ToolExecutionPlan | ToolExecutionBlocked
```

竖线 `|` 表示结果可能是左边类型，也可能是右边类型。

### 第一遍检查

方法先遍历全部工具调用：

```python
for tool_call in tool_calls:
```

对每一个调用检查：

- Registry 中是否存在这个工具。
- 当前 Agent Mode 是否允许这个工具。

只要发现一个非法调用，就立即返回 `ToolExecutionBlocked`。因此同一轮的其他工具也不会执行。

这是“先整体验证，再产生副作用”的策略，可以避免执行了一半才发现后面有非法工具。

### 第二遍分批

只有全部调用都合法，才开始分批。

连续只读工具先放入 `current_read_only`。遇到有副作用工具时：

1. 把之前积累的只读工具形成一批。
2. 把当前副作用工具单独形成一批。

最后再把剩余只读工具形成一批。

### 内部函数 `flush_read_only`

函数里面还可以定义函数：

```python
def flush_read_only() -> None:
```

这个小函数只服务于 `build_plan`，作用是把暂存的只读调用倒进正式批次。

它能直接访问外层函数里的 `batches` 和 `current_read_only`。这种能力叫闭包。

## 七、`execute_plan`：按批次执行

如果是只读批次：

```python
results = await asyncio.gather(
    *(self._execute_one(tool_call) for tool_call in batch.tool_calls)
)
```

它会并发等待多个只读工具。

### 语法：生成器表达式

```python
(self._execute_one(x) for x in items)
```

表示为每个 `x` 创建一次异步调用。

### 语法：星号 `*`

这里把一组异步调用展开成 `asyncio.gather` 的多个参数。

### 为什么还要 `zip`

并发完成后：

```python
for tool_call, result in zip(batch.tool_calls, results):
```

把原始调用和对应结果配对，并按原始顺序产生事件。即使第二个读取先完成，交给模型时仍维持模型最初请求的顺序。

有副作用批次则使用普通 `for` 循环，一个执行完再执行下一个。

## 八、`_execute_one`：单个工具的生命过程

流程如下：

```text
解析 JSON 参数
→ 从 Registry 找工具
→ tool.prepare(...)
→ 如果准备失败，返回错误结果
→ tool.execute(...)
→ 返回执行结果
```

### 为什么分 `prepare` 和 `execute`

`prepare` 应该只做执行前工作：

- 校验参数。
- 解析目标路径。
- 检查路径边界。
- 生成操作摘要。
- 返回 `PreparedToolCall`。

`execute` 才真正：

- 读取或写入文件。
- 修改内容。
- 启动 Shell 命令。

这条边界对权限系统非常关键。权限询问必须发生在 `prepare` 之后、`execute` 之前，因为：

- `prepare` 前还不知道准确影响目标。
- `execute` 后再询问已经太晚。

## 九、JSON 参数解析

模型返回的工具参数是 JSON 字符串：

```json
{"path": "demo.py"}
```

`json.loads` 把它转换为 Python 字典：

```python
{"path": "demo.py"}
```

### 语法：`try/except`

如果 JSON 格式错误，`json.loads` 会抛出 `JSONDecodeError`。代码捕获异常后返回结构化工具错误，而不是让整个程序崩溃。

### 语法：`isinstance`

```python
if not isinstance(parsed, dict):
```

用于在运行时判断对象是否属于某个类型。这里要求工具参数必须是 JSON 对象，而不能是数组或普通字符串。

## 十、ch06 的关键改造位置

当前 `_execute_one` 在准备成功后直接执行：

```text
prepared = tool.prepare(...)
→ tool.execute(...)
```

未来权限流程大致会变成：

```text
prepared = tool.prepare(...)
→ 权限规则评估 prepared.preview
→ 自动允许 / 询问用户 / 直接拒绝
→ 获得允许后 tool.execute(...)
```

需要特别考虑：只读批次目前可以并发执行。如果某些只读操作也可能询问权限，权限询问不能在终端中同时弹出多个，否则交互会混乱。

## 十一、阅读练习

试着手工为下面的顺序分批：

```text
read_file
find_files
run_command
write_file
search_text
```

预期：

```text
第 1 批：read_file + find_files
第 2 批：run_command
第 3 批：write_file
第 4 批：search_text
```

如果你能解释为什么副作用工具各自单独成批，就理解了这个文件的核心。
