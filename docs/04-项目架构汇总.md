## 3. 各层详细设计

### 3.1 入口层

**文件：** `artcode/cli.py`、`artcode/__main__.py`

```
main()  →  asyncio.run(run_app())  →  组装各层  →  runtime.run()
  │               │                       │
  └─ 函数入口      └─ 创建事件循环            └─ 依赖注入（手动）
```

```python
async def run_app(config_path: Path | None = None) -> int:
    renderer = TuiRenderer()
    try:
        config = load_config(config_path)          # 配置层
    except ConfigError as exc:
        renderer.show_startup_error(exc)            # 启动失败 → 直接退出
        return 2

    provider = OpenAICompatibleProvider(config)      # Provider 层
    runtime = ArtCodeRuntime(                        # 手动依赖注入
        config=config,
        provider=provider,
        conversation=ConversationContext(),          # 对话上下文层
        tui=PromptToolkitTui(renderer=renderer),     # TUI 层
    )
    return await runtime.run()
```

**退出码：**
| 码 | 含义 |
|----|------|
| 0 | 正常退出（`/exit` 或 Ctrl+C 在输入态） |
| 2 | 配置错误（启动失败） |
| 130 | SIGINT 收到（`KeyboardInterrupt` 在外部） |

**文件：** `artcode/config.py`

**数据流：**

```
artcode.yaml  →  yaml.safe_load()  →  dict  →  parse_config()  →  ArtCodeConfig (frozen dataclass)
                                                      │
                                              ┌───────┴───────┐
                                              │  逐字段类型校验  │
                                              │  不依赖 Pydantic │
                                              └───────────────┘
```

**配置结构：**

```yaml
# artcode.yaml

api_key: sk-xxxx          # 敏感信息，.gitignore

  enabled: false
```

**安全性设计：**

```python
@dataclass(frozen=True)
class SafeConfigStatus:       # 脱敏后的配置 → 给 TUI 展示
    protocol: str
    model: str
    base_url: str
    masked_api_key: str       # "sk-e4...8567d"
    # 不包含 api_key 原文！
```

### 3.3 Runtime 层

**文件：** `artcode/runtime/app.py`

**核心：主循环状态机**

```
                    ┌──────────────────────────────────┐
                    │         等待用户输入               │
                    │    tui.read_input(model)          │
                    └──────────┬───────────────────────┘
                               │
                    ┌──────────▼───────────┐
                    │    是否为空输入？      │
                    └────┬─────────┬───────┘
                    是   │         │  否
                    ┌────▼──┐  ┌───▼──────────┐
                    │ 跳过   │  │  是否命令？    │
                    └───────┘  └──┬────────┬───┘
                             是   │        │  否
                         ┌───────▼──┐  ┌──▼──────────┐
                         │ 执行命令  │  │  追加user    │
                         │ /exit→退出│  │  调用Provider│
                         │ /help→显示│  │  流式渲染    │
                         └──────────┘  │  追加assistant│
                                       └──────────────┘
```

**取消处理时序：**

```
用户按Ctrl+C
    │
    ├── 输入等待状态 → UserRequestedExit → 退出程序 (return 0)
    │
    └── 生成进行中 → signal.SIGINT → task.cancel()
                        │
                        ▼
                  CancelledError 被捕获
                        │
                        ├── 返回 None（不写入上下文）
                        └── TUI 显示 "已取消，本轮半截回复未写入上下文"
```

### 3.4 Provider 层

**文件：** `artcode/providers/`（4 个文件，~200 行）

**模块职责：**

| 文件 | 职责 | 对外接口 |
|------|------|---------|
| `base.py` | Provider 协议定义 | `StreamingProvider` Protocol |
| `events.py` | 事件类型常量和工厂 | `content_delta_event()`, `done_event()` |
| `sse.py` | SSE 流解析器 | `SSEDecoder`, `parse_sse_lines()` |
| `openai_compatible.py` | DeepSeek 实现 | `OpenAICompatibleProvider` |

**HTTP 请求流程：**

```
OpenAICompatibleProvider.stream_chat(messages)
    │
    ├── build_request_payload()        → 构造请求体（含 thinking 映射）
    ├── httpx.AsyncClient.stream()     → POST /chat/completions
    │       │
    │       ├── 状态码 >= 400 → map_http_error() → 抛出 RequestError 子类
    │       │
    │       └── 状态码 200 → response.aiter_lines()
    │               │
    │               └── SSEDecoder.feed(line)
    │                       │
    │                       ├── data: {"choices":[{"delta":{"content":"你好"}}]}
    │                       │       → content_delta_event("你好")
    │                       │
    │                       └── data: [DONE]
    │                               → done_event()
    │
    └── 异常处理 → httpx 异常 → ArtCodeError 子类
```

**错误映射表：**

| httpx 异常 | ArtCode 错误 | HTTP 状态码 |
|-----------|-------------|------------|
| `TimeoutException` | `TimeoutError` | — |
| `ConnectError`, `NetworkError` | `NetworkError` | — |
| `RemoteProtocolError`, `ReadError`, `DecodingError` | `StreamInterruptedError` | — |
| 响应 401/403 | `AuthenticationError` | 401, 403 |
| 响应 400/404/422 | `ModelError` | 400, 404, 422 |
| 响应含 "thinking" 关键词 | `ThinkingModeUnsupportedError` | 400 |

### 3.5 TUI 层

**文件：** `artcode/tui/`（3 个文件，~120 行）

```
┌─────────────────────────────────────────────┐
│                  TuiRenderer                 │  纯渲染，不管理输入
│  • show_startup()  →  启动面板 (rich Panel)  │
│  • stream_delta()  →  流式输出 (无换行)       │
│  • show_error()    →  红色错误               │
│  • show_help()     →  青色帮助文本            │
└─────────────────────────────────────────────┘
                       ▲
                       │ 被 PromptToolkitTui 持有
                       │
┌─────────────────────────────────────────────┐
│              PromptToolkitTui                │  管理输入 + 委托渲染
│  • read_input()    →  prompt_async()         │
│  • 封装 PromptSession（multiline）           │
│  • 暴露 UserRequestedExit 异常               │
└─────────────────────────────────────────────┘
                       ▲
                       │ 快捷键由 keybindings.py 定义
                       │
┌─────────────────────────────────────────────┐
│              Key Bindings                    │
│  Enter         →  发送输入                   │
│  Ctrl+J        →  插入换行                   │
│  Esc + Enter   →  插入换行（备用）            │
└─────────────────────────────────────────────┘
```

**设计约束：**
- TuiRenderer 不依赖 prompt_toolkit → 可单独测试
- PromptToolkitTui 不依赖 ArtCodeRuntime → 可替换为其他 TUI 实现
- TUI 层不持有 Provider → 不关心模型细节
- 流式输出使用 `markup=False` → 避免 AI 回复中的标记被 rich 误解析

### 3.6 对话上下文层

**文件：** `artcode/conversation/context.py`（26 行）

```python
class ConversationContext:
    def __init__(self, system_prompt: str = SYSTEM_PROMPT) -> None:
        self._messages: list[Message] = [{"role": "system", "content": system_prompt}]

    def append_user(self, content: str) -> None:
        self._append("user", content)

    def append_assistant(self, content: str) -> None:
        self._append("assistant", content)

    def export_messages(self) -> list[Message]:
        return deepcopy(self._messages)         # 返回副本，防止外部修改
```

**设计考量：**
- 极简实现 → 26 行代码，职责单一
- `deepcopy` → 防止 Runtime 层拿到引用后意外修改
- 不持久化 → ch02 只支持单次会话
- 不裁剪 → 对话过长时依赖 API 返回错误
- `_messages` 用 `_` 前缀 → convention 表示"不要直接访问"

### 3.7 命令系统层

**文件：** `artcode/commands/`（2 个文件，~45 行）

```python
class CommandRegistry:
    def __init__(self) -> None:
        self._handlers: dict[str, CommandHandler] = {}

    def register(self, name: str, handler: CommandHandler) -> None:
        if not name.startswith("/"):
            raise ValueError("Slash command names must start with '/'.")
        self._handlers[name] = handler

    def handle(self, user_input: str) -> CommandResult | None:
        command = user_input.strip()
        if "\n" in command:
            return None                         # 多行不可能是命令
        handler = self._handlers.get(command)
        return handler(command) if handler else None
```

**扩展方式：** 后续添加新命令只需 `registry.register("/newcmd", handler)`。

### 3.8 错误系统层

**文件：** `artcode/errors.py`（68 行）

**层次结构：**

```
Exception
  └── ArtCodeError            (message + hint → user_message)
        ├── ConfigError        (启动阶段致命错误)

              ├── ModelError              (400/404/422)
              ├── TimeoutError            (超时)
              ├── ThinkingModeUnsupportedError
              └── StreamInterruptedError  (流式中断)
```

## 4. 数据流全景

### 4.1 一轮完整对话的数据流

```
1. 用户输入
   prompt_toolkit → "什么是闭包？"
                           │
2. Runtime 主循环           │
   commands.handle()       ← 先检查是否为命令（否）
   conversation.append_user("什么是闭包？")
                           │
3. Provider 调用            │
   export_messages()       ← [system, user:"什么是闭包？"]
   build_request_payload() ← stream=True, thinking=off
   httpx POST /chat/completions
                           │
4. 流式响应                 │
   SSE: data: {"choices":[{"delta":{"content":"闭包是指"}}]}
   SSEDecoder.feed()       → SSEEvent(data=..., done=False)
   _events_from_sse_data() → content_delta_event("闭包是指")
                           │
5. TUI 流式渲染             │
   tui.stream_delta("闭包是指") → console.print("闭包是指", end="")
                           │ ... (持续流式输出)
                           │
6. 流结束                   │
   SSE: data: [DONE]
   SSEDecoder.feed()       → SSEEvent(done=True)
   done_event()             │
   tui.finish_assistant_message()
                           │
7. 写入上下文               │
   conversation.append_assistant("闭包是指一个函数...")
   → 下一轮对话可以引用前文
```

### 4.2 配置加载的数据流

```
artcode.yaml (文件)
    │
    ▼
yaml.safe_load()
    │
    ▼
dict {"protocol": "openai", "model": "deepseek-chat", ...}
    │
    ▼
parse_config(dict)
    ├── _required_non_empty_string("protocol") → "openai"
    ├── _required_non_empty_string("model")    → "deepseek-chat"
    ├── _required_non_empty_string("base_url") → "https://api.deepseek.com"
    ├── _required_non_empty_string("api_key")  → "sk-xxxx"
    └── _parse_thinking(raw["thinking"])       → ThinkingConfig(enabled=False, effort="high")
    │
    ▼
ArtCodeConfig (frozen dataclass)
    │
    ├── .safe_status() → SafeConfigStatus (脱敏，给 TUI 展示)
    └── 原对象传给 OpenAICompatibleProvider (含完整 api_key)
```

## 5. 依赖关系

### 5.1 模块依赖图

```
cli.py ──────────────────────────────────────────────
  │                                                    │
  ├── config.py ─── errors.py                          │
  ├── providers/ ─── errors.py, config.py, events, sse │
  ├── conversation/ ─── prompts.py                     │
  ├── commands/ ─── (无外部依赖)                        │
  ├── runtime/ ─── config, commands, conversation,     │
  │                providers, tui, errors              │
  └── tui/ ─── config, errors, keybindings             │
```

### 5.2 依赖原则

| 原则 | 说明 |
|------|------|
| **单向依赖** | 上层依赖下层，下层不依赖上层 |
| **核心向内** | `errors.py` 只被所有层依赖，它不依赖任何业务层 |
| **TUI 隔离** | TUI 层不感知 Provider 细节，不感知 Runtime 编排 |
| **Provider 隔离** | Provider 层不感知 TUI 渲染，不感知对话上下文 |

**测试策略：**
- 单元测试不依赖外部服务 → 快速、可重复

- 集成测试放在单独目录 → 明确标注会消耗 API 额度
- `pytest-asyncio` 的 `asyncio_mode = "auto"` → 无需手动标记 async 测试

## 7. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 不使用 OpenAI SDK | 手动 httpx + SSE | 学习 HTTP 流式响应机制 |
| 不使用 Pydantic | 手写 dataclass + 校验 | 减少依赖，理解校验逻辑 |
| 不使用 LangChain | 从零实现 | 学习 Agent 底层架构 |
| 不使用 async click/typer | prompt_toolkit + rich | 更好的流式输出体验 |
| Protocol 而非 ABC | 结构化子类型 | 更轻量，支持鸭子类型 |
| frozen dataclass | 不可变配置 | 防止运行时意外修改 |
| deepcopy 导出 | 防御性拷贝 | 防止内部状态被外部修改 |
| 中文错误提示 | 面向新手 | 降低学习门槛 |
