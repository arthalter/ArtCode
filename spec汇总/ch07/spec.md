# ch07：MCP协议 Spec

## 背景

ArtCode 当前只有内置工具。每增加一种外部能力，都需要按照 ArtCode 的工具接口单独开发、注册和维护，无法直接复用 MCP 生态中的现有 Server。

ch07 将引入标准 MCP 客户端，使用户可以分别在用户级配置和项目级配置中声明外部 MCP Server。ArtCode 启动时连接获准且启用的 Server，完成初始化并发现其工具，再将这些工具接入现有工具中心。Agent 继续通过统一工具调用机制使用工具，不需要了解底层 Server、传输方式或 MCP 协议细节。

外部 Server 彼此隔离。单个 Server 配置错误、连接失败、协议异常或运行中断开，不得影响其他 MCP Server、内置工具或 ArtCode 主流程。

## 目标

- 支持通过本地 stdio 子进程和远程 Streamable HTTP 连接 MCP Server。
- 使用官方 Python MCP SDK 完成标准初始化、消息关联和协议通信。
- 在启动阶段自动完成 Server 初始化和工具发现。
- 将发现的 MCP 工具适配为 ArtCode 统一工具，并注册到现有工具中心。
- 让 Agent 使用 MCP 工具时保持与内置工具一致的调用和结果回灌体验。
- 支持用户级与项目级两层 Server 配置，并按 Server 名进行确定性覆盖。
- 缓存已建立的 Server 会话，允许同一 Server和不同 Server 的获准调用并发执行。
- 隔离单个 Server 的配置、连接、协议和调用故障。
- 对所有 MCP 工具调用执行人工确认，包括 Plan 模式中的调用。
- 在退出和取消时管理连接、请求及 stdio 子进程的生命周期。
- 保持本章范围聚焦于 MCP 工具，不扩展到 MCP 的其他能力。

## 功能需求

### 配置加载与合并

- F1：ArtCode 从用户级主配置读取 MCP Server 列表，并从当前 Workspace 的项目级配置读取项目 MCP Server 列表。
- F2：项目级配置只接受 MCP Server 设置，不得覆盖模型、API 凭证、思考模式等用户级主配置。
- F3：使用自定义主配置路径启动时，该文件作为用户级配置基底，项目级 MCP 配置仍继续参与合并。
- F4：两层配置按 Server 名合并；同名项目级配置完整替换用户级配置，不执行字段级继承。
- F5：每个 Server 可以被显式启用或禁用；禁用项不建立连接、不发现工具。
- F6：stdio Server 接受命令、参数和环境变量配置；Streamable HTTP Server 接受 URL 和 Headers 配置。
- F7：环境变量和 Header 值支持 `${VAR}` 展开；引用不存在的变量时，只跳过对应 Server并指出缺失变量名。
- F8：Server 配置采用严格校验；未知字段、传输字段混用或必填信息缺失时，只跳过对应 Server。
- F9：stdio 子进程以当前 Workspace 为默认工作目录，并只继承安全基础环境变量及配置显式注入的变量。
- F10：项目级 Server 在建立连接或启动进程前必须逐项获得用户确认；用户级 Server 默认视为用户主动配置。
- F11：没有配置任何 Server，或没有任何 Server 成功连接时，ArtCode 仍使用内置工具正常启动。

### 连接与协议会话

- F12：ArtCode 支持 stdio 和 Streamable HTTP 两种 MCP 传输。
- F13：每个已获准 Server 建立独立客户端会话，并按照 MCP 标准完成初始化协商。
- F14：完成初始化后，ArtCode 获取 Server 工具列表并处理分页，直到列表结束或达到安全边界。
- F15：多个 Server 以有界并发方式完成连接、初始化和工具发现，单个慢 Server 不阻塞其他 Server。
- F16：初始化、工具发现和工具调用分别受超时约束。
- F17：Streamable HTTP 可以跟随同源及跨域重定向，并在跨域后原样转发配置中的全部自定义 Headers。
- F18：stdio Server 的标准错误流被持续消费；正常运行时不干扰 TUI，故障时可以提供有限、脱敏的近期诊断信息。
- F19：本章只使用启动时发现的工具快照；Server 在会话中改变工具列表时，不动态增删已注册工具。

### 工具适配与注册

- F20：每个远端工具被包装为符合 ArtCode 现有统一调用流程的工具。
- F21：注册名称统一包含 MCP 标识、Server 命名空间和远端工具名，以避免内置工具与不同 Server 之间直接重名。
- F22：不兼容模型函数命名约束的字符会被确定性规范化；规范化后发生冲突时，只跳过冲突工具。
- F23：合法工具 Schema 被传递给模型；Schema 缺失、无效或与当前模型工具接口不兼容时，只跳过对应工具。
- F24：远端工具没有描述时，ArtCode 为其生成能够说明来源的回退描述。
- F25：单个 Server 返回过多工具或异常分页时，ArtCode 保留安全边界内的工具，并报告截断情况。
- F26：工具注册结果具有确定性，不受并行连接完成顺序影响。
- F27：内置工具始终可用；单个 MCP 工具无效或冲突不得影响其他合法工具。

### 调用、确认与结果

- F28：Agent 调用 MCP 工具时，通过对应的缓存会话向正确 Server 发起标准工具调用。
- F29：所有 MCP 工具调用都必须逐次获得用户确认，不因当前权限模式或 Server 提供的只读提示而自动放行。
- F30：Plan 模式向模型暴露 MCP 工具；用户确认后允许执行，即使 ArtCode 无法保证该工具只读。
- F31：确认界面显示 Server、工具名和脱敏后的调用参数；超长参数受到展示限制。
- F32：同一 Server 与不同 Server 的多个已获准调用可以并发，响应必须与原始请求正确配对。
- F33：文本结果直接回灌；结构化内容以文本化 JSON 回灌；图片、音频、资源等非文本内容只回灌安全元数据，不直接注入二进制内容。
- F34：MCP 工具结果使用 ArtCode 现有统一结果结构和内容大小限制，并可观测地标记截断。
- F35：Server 返回的工具业务错误和 JSON-RPC 错误被转换为结构化失败结果，不导致整个 Agent Loop 崩溃。
- F36：普通工具错误后保留仍然健康的 Server 会话；传输断开、协议损坏或调用超时后关闭对应会话，并在本次 ArtCode 进程中标记为不可用。
- F37：已标记不可用的 Server 不自动重连；后续调用获得明确、快速的不可用结果。

### 生命周期与故障隔离

- F38：每个 Server 的连接、会话状态、工具列表和诊断信息独立管理。
- F39：单个 Server 在配置、确认、启动、初始化、发现或调用阶段失败时，其他 Server、内置工具和 ArtCode 主流程继续工作。
- F40：用户取消正在执行的 MCP 调用时，ArtCode 尝试向 Server 传播取消；连接仍正常时继续复用，否则关闭并标记不可用。
- F41：ArtCode 退出时停止接受新的 MCP 调用，取消未完成请求，并关闭所有 HTTP 会话。
- F42：ArtCode 退出时优雅结束 stdio Server；超过关闭宽限期仍未退出的子进程会被终止，单个卡住的进程不得阻塞整体退出。
- F43：启动界面显示 MCP 配置数、成功连接数、失败数和已注册工具数，并显示每个 Server 的成功或脱敏失败状态。

## 非功能需求

### 兼容性

- N1：实现基于官方 Python MCP SDK 的稳定版本，不自行复制或重新实现完整协议栈。
- N2：客户端遵循 Server 协商出的 MCP 协议版本与能力，不假设所有 Server 支持相同扩展。
- N3：MCP 接入不得破坏现有内置工具、Agent Loop、多工具调度、权限确认和结果回灌行为。
- N4：不要求外部 Server 使用 Python 实现，只要符合 MCP 标准并支持指定传输即可接入。

### 可靠性与隔离

- N5：配置解析、连接、初始化、工具发现、工具调用和关闭均以单个 Server 为故障隔离边界。
- N6：所有网络、子进程、协议请求和关闭等待都必须有界，不能无限阻塞 ArtCode。
- N7：并发初始化和并发调用必须避免竞态、响应串线、重复关闭及遗留后台任务。
- N8：关闭、取消和超时操作应具备幂等性；重复触发不得导致 ArtCode 崩溃。
- N9：工具注册顺序、名称规范化和冲突处理必须可重复，不受异步完成顺序影响。
- N10：Server 变为不可用后，后续调用应快速失败，不继续等待已经失效的连接。

### 安全性

- N11：环境变量展开后的值、HTTP Headers、工具参数和 Server 日志不得以明文出现在启动摘要或错误信息中。
- N12：stdio Server 默认不得继承 ArtCode 主进程中的全部环境变量，只提供安全运行所需的基础环境。
- N13：项目级 Server 必须在产生子进程执行或网络请求前获得用户确认。
- N14：确认界面必须让用户看清将启动的命令或连接的 URL，以及会引用哪些环境变量和 Header。
- N15：所有 MCP 工具都视为潜在副作用工具，不能仅凭 Server 自述的只读注解绕过人工确认。
- N16：允许跨域 HTTP 重定向并原样转发自定义 Headers 是用户明确接受的兼容性选择；启动确认和文档必须清楚提示凭证可能被重定向目标接收。
- N17：远端返回的二进制、多媒体和资源内容不能不受限制地进入模型上下文。
- N18：来自 Server 的错误、日志、描述、Schema 和结果均视为不可信输入，展示和序列化时不得破坏 TUI 或结果结构。

### 性能与资源

- N19：多个 Server 的启动发现采用有界并发，避免慢 Server 形成串行累积等待。
- N20：工具分页数量、诊断日志、参数预览和结果内容均设置明确上限。
- N21：已建立的会话在进程内复用，不能为每次工具调用重复初始化 Server。
- N22：stdio 的标准输出只用于 MCP 协议通信，标准错误必须持续消费，防止管道背压造成死锁。
- N23：退出后不得遗留由 ArtCode 启动且仍由其负责的 stdio Server 进程。

### 可观测性与可测试性

- N24：启动状态能够区分配置、用户拒绝、传输、初始化、工具发现、工具校验和注册冲突等失败阶段。
- N25：所有用户可见错误必须包含 Server 名和可操作原因，但不得包含秘密值。
- N26：核心协议编排、配置合并、适配、故障隔离和生命周期行为应可通过注入假 Server 与假传输进行确定性测试。
- N27：stdio 和 Streamable HTTP 均需要真实本地 MCP Server 集成测试，不能只验证模拟对象。
- N28：端到端验证必须证明 Agent 能发现、确认并调用 MCP 工具，再把结果回灌给模型流程。
- N29：现有测试必须继续通过，并补充正常、拒绝、超时、断连、分页、冲突、取消及关闭等边缘场景。
- N30：实现保持模块职责清晰，使配置、传输会话、工具适配和 Runtime 生命周期可以独立测试。

## 不做的事

- 不实现 MCP Resources 的发现、读取或订阅。
- 不实现 MCP Prompts 的发现和调用。
- 不响应 MCP Sampling 请求，不允许 Server 借用 ArtCode 的模型生成内容。
- 不实现 MCP Roots、Elicitation、Tasks 等扩展能力。
- 不实现旧式 HTTP+SSE 传输，只支持 stdio 和 Streamable HTTP。
- 不自行实现一套完整 JSON-RPC 或 MCP 协议栈。
- 不开发或托管 MCP Server，只实现 ArtCode 客户端。
- 不实现 Server 健康检查、心跳或后台状态轮询。
- 不实现连接断开后的自动重连、退避和会话恢复。
- 不在运行期间动态刷新 Server 发出的工具列表变化。
- 不提供运行期间新增、删除、启用或停用 Server 的命令。
- 不提供 MCP Server 管理界面、配置编辑器或安装市场。
- 不实现项目级 Server 的永久信任记录；项目级 Server 每次启动仍需确认。
- 不根据 MCP 工具的只读或破坏性注解自动调整权限策略。
- 不允许 MCP 工具绕过每次调用的人工确认。
- 不为不同 MCP 工具配置独立权限规则或长期允许规则。
- 不让 MCP 工具自动获得 ArtCode 内置文件工具的 Workspace 路径保证。
- 不自动限制外部 Server 进程自身能够访问的文件和网络范围；用户确认启动即表示信任该外部进程。
- 不实现 HTTP OAuth 登录、动态客户端注册、浏览器授权或令牌刷新；首版只使用配置中的 Headers。
- 不支持 Unix Socket、WebSocket 或自定义传输。
- 不支持为单个 Server 自定义超时、工具数量上限、并发数或关闭宽限期。
- 不把图片、音频或其他二进制 MCP 内容直接作为多模态消息发送给模型。
- 不持久化 Server 会话、工具列表或调用结果；ArtCode 重启后重新初始化和发现。
- 不保证协议取消一定能停止 Server 已经开始的外部副作用。
- 不支持 Server 主动请求用户输入或调用 ArtCode 的其他客户端能力。
- 不将 Server 的日志通知实时输出到 TUI；只保留规定范围内的诊断信息。
- 不因某个 MCP Server 不可用而阻止 ArtCode 使用内置工具启动。

## 验收标准

### 配置与合并

- AC1：只有用户级配置时，所有启用且合法的 Server 都进入启动发现流程。
- AC2：项目级配置只包含 `mcp_servers` 时可以正常加载；出现其他顶层配置时给出明确错误，且不覆盖用户级主配置。
- AC3：使用 `--config` 指定主配置后，指定文件中的 Server 与 Workspace 项目级 Server 正常合并。
- AC4：用户级和项目级存在同名 Server 时，最终配置完全等于项目级条目，不继承用户级条目的任何字段。
- AC5：配置为禁用的 Server 不产生子进程或网络请求，也不注册工具。
- AC6：合法 stdio 配置能够读取命令、参数和环境变量；合法 Streamable HTTP 配置能够读取 URL 和 Headers。
- AC7：`env` 与 `headers` 中的 `${VAR}` 能正确展开；变量不存在时只跳过对应 Server，错误显示变量名但不显示其他秘密值。
- AC8：未知字段、字段拼写错误、传输字段混用、必填字段缺失和无效字段类型均只使对应 Server 失效。
- AC9：stdio Server 的相对路径以 Workspace 为基准，并且只继承验收清单规定的基础环境变量和显式配置变量。
- AC10：项目级 stdio 或 HTTP Server 在用户确认前不会启动进程、解析秘密值后发送请求或建立连接。
- AC11：用户拒绝项目级 Server 后，该 Server 被跳过，其他 Server 和内置工具继续启动。
- AC12：没有 `mcp_servers`、所有 Server 被禁用、全部被拒绝或全部失败时，ArtCode 均能以仅内置工具模式启动。

### 传输与会话

- AC13：真实本地 stdio MCP Server 能完成初始化、分页列出工具和工具调用。
- AC14：真实本地 Streamable HTTP MCP Server 能完成初始化、分页列出工具和工具调用。
- AC15：客户端与 Server 完成标准能力和协议版本协商；协商失败时只关闭对应 Server。
- AC16：一个 Server 的连接、初始化或工具发现超时，不影响其他 Server 在自身时限内完成启动。
- AC17：多个 Server 同时配置时，启动并发数不超过验收清单规定的上限。
- AC18：循环游标、无限分页或工具数量超限不会无限阻塞启动；系统保留边界内的工具并报告截断。
- AC19：Streamable HTTP 的同源和跨域重定向均可继续连接。
- AC20：发生跨域重定向时，配置中的普通和敏感自定义 Headers 均原样转发，并在相关安全说明中明确提示风险。
- AC21：stdio Server 持续大量写入 `stderr` 时不会因管道塞满而挂起；正常运行时日志不刷入 TUI。
- AC22：stdio Server 失败时，错误信息可包含规定范围内的近期脱敏日志，且不会无限增长。
- AC23：Server 发出工具列表变化通知后，当前会话中的工具注册表保持不变；重启 ArtCode 后重新发现。

### 工具注册

- AC24：发现到的合法 MCP 工具出现在发送给模型的工具列表中，并能通过 ArtCode 工具中心按注册名找到。
- AC25：注册名采用 `mcp__<server>__<tool>` 结构，不会直接覆盖内置工具。
- AC26：Server 名或工具名含空格、点、斜杠及其他不兼容字符时，注册名按统一规则规范化。
- AC27：名称过长时生成符合模型限制且稳定可重复的名称；规范化后重名时只跳过冲突工具。
- AC28：工具 Schema 合法且兼容时保持原有参数语义；Schema 无效或不兼容时只跳过该工具。
- AC29：缺少描述的工具获得包含 Server 和原工具名称的回退描述。
- AC30：单个 Server 中某个工具无效、超限或冲突时，该 Server 的其他合法工具仍然注册。
- AC31：以不同连接完成顺序重复启动时，最终工具顺序、注册名和冲突结果一致。
- AC32：新增 MCP 工具后，现有内置工具仍完整存在并可正常调用。

### 调用、确认与结果

- AC33：模型调用注册后的 MCP 工具时，请求被路由到正确 Server 和正确远端工具名。
- AC34：每次 MCP 工具调用都进入人工确认；Default、Edit、Full 以及 Server 的只读注解均不能自动放行。
- AC35：Plan 模式的模型请求包含 MCP 工具，用户允许后能够执行并返回结果。
- AC36：用户拒绝调用后不会向 Server 发送 `tools/call`，并向 Agent 返回结构化拒绝结果。
- AC37：确认界面显示 Server、工具名和参数；敏感键值被隐藏，超长参数按验收清单规定截断。
- AC38：同一 Server 存在多个并发调用时，每个结果都与正确的原请求关联，不发生串线。
- AC39：不同 Server 并发调用时，一个慢调用不阻止另一个调用先完成。
- AC40：文本内容、结构化内容和混合内容能按约定转换为 ArtCode 文本结果。
- AC41：图片、音频、嵌入资源等内容只产生类型、MIME、URI、大小等安全元数据，不直接回灌二进制数据。
- AC42：序列化结果超过现有工具限制时按 UTF-8 边界截断，并标记结果已截断。
- AC43：MCP 业务错误、`isError` 结果和 JSON-RPC 错误均转换为可识别的失败结果，不导致 Agent Loop 崩溃。
- AC44：普通参数或业务错误后，同一健康会话仍可执行下一次工具调用。
- AC45：传输断开、协议损坏或调用超时后，对应 Server 被关闭并标记不可用。
- AC46：不可用 Server 的后续调用快速返回明确错误，不进行自动重连；其他 Server 仍可调用。

### 生命周期与隔离

- AC47：每个 Server 独立保存会话、状态、工具和诊断信息，一个 Server 的状态变化不会误改另一个 Server。
- AC48：配置错误、用户拒绝、进程启动失败、HTTP 失败、握手失败、工具发现失败和注册失败均能隔离到对应 Server 或工具。
- AC49：用户取消进行中的普通 MCP 请求时，ArtCode 尝试传播协议取消，并停止等待该结果。
- AC50：取消与响应同时发生时，不重复回灌结果、不泄漏后台任务，也不导致重复关闭异常。
- AC51：普通取消后连接仍健康时可以继续复用；连接损坏时关闭并标记不可用。
- AC52：初始化超时或取消通过关闭对应传输处理，不发送规范禁止的初始化取消通知。
- AC53：正常退出时不再接受新调用，未完成调用被取消，HTTP 会话均被关闭。
- AC54：正常退出时，由 ArtCode 启动的 stdio Server 在宽限期内结束；拒绝退出者被终止。
- AC55：一个 Server 在关闭时卡住或报错，不阻止其他 Server 清理，也不阻止 ArtCode 在总时限内退出。
- AC56：退出完成后没有遗留由本次 ArtCode 会话负责的 stdio Server 进程。

### 启动状态、安全与回归

- AC57：启动界面显示 MCP 配置数、成功数、失败数和注册工具数。
- AC58：成功项显示 Server 名和工具数量；失败项显示 Server 名、失败阶段和脱敏原因。
- AC59：启动状态、确认界面、异常、近期日志和工具结果均不泄露展开后的环境变量秘密或敏感 Header 值。
- AC60：项目级 Server 启动确认明确展示 stdio 命令及参数，或 HTTP 初始 URL，并列出引用的环境变量名和 Header 名。
- AC61：安全说明明确告知：外部 stdio 进程不受 ArtCode 文件工具 Workspace 沙箱保护，跨域重定向会原样转发自定义 Headers。
- AC62：所有新增单元测试、stdio 与 HTTP 集成测试、现有完整测试集均通过。
- AC63：真实端到端场景中，ArtCode 启动后发现 MCP 工具，Agent 发起调用，用户确认，Server 返回结果，结果进入后续模型轮次。
- AC64：故障端到端场景中，一个 MCP Server 在运行中断开，另一个 MCP Server 和内置工具仍能完成调用。

具体超时秒数、并发上限、分页工具上限、日志行数、参数展示长度、名称长度和关闭宽限期将在 `plan.md` 中设计，并作为可直接勾选的固定值写入 `checklist.md`。
