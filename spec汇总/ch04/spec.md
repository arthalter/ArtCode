# ch04：动手实现 Agent Loop Spec

## 背景

ArtCode 在 ch03 已经具备第一版工具系统：模型可以请求本地工具，ArtCode 可以执行工具、处理结构化结果，并把工具结果回灌给模型。但 ch03 仍是“单步工具流”：一次用户输入最多执行一轮工具，然后强制进入最终总结，模型不能根据工具结果继续自主搜索、修改、验证和修正。

ch04 的目标是把 ArtCode 从“会调用一次工具的助手”推进到“能自主循环干活的 Agent”。用户输入任务后，ArtCode 默认进入 Agent Loop：模型可以一轮轮观察上下文、请求工具、读取工具结果、调整下一步动作，直到模型自然完成、触发停止条件，或用户取消。

这一章同时引入 Plan Mode 的两段式工作流：用户通过 `/plan 任务描述` 让模型只使用读类工具先理解项目并生成计划；计划会保存为本次运行内的最近计划；用户确认后通过 `/do` 或 `/do 附加说明` 开放全工具执行最近计划。

## 目标用户

- 正在学习 CLI Coding Agent 核心循环的新手开发者。
- 希望理解 ReAct 模式中“模型思考、工具行动、结果观察、继续调整”完整链路的项目作者。
- 希望在本地学习项目中体验“普通输入即自主执行、Plan Mode 先规划后执行”的用户。

## 本章目标

- 让普通用户输入默认进入最多 12 轮的 Agent Loop。
- 让模型能够在每一轮根据上一轮工具结果继续请求工具或自然结束。
- 提供异步事件流，把 Agent 内部执行过程和 TUI 展示解耦。
- 让流式文本既能实时显示，又能被完整收集用于后续判断。
- 支持一次模型响应返回多个工具调用，并按安全性分批执行。
- 让相邻只读工具可以并发执行，有副作用工具按原始顺序串行执行。
- 支持 `/plan 任务描述` 只使用读类工具生成计划。
- 支持 `/do` 执行最近计划，支持 `/do 附加说明` 在执行时追加约束。
- 明确停止条件：模型自然完成、达到 12 轮上限、用户取消、未知工具、流式错误。
- 暂不引入权限系统、上下文压缩和用户交互式确认，把这些留给后续章节。

## 功能需求

- F1: ArtCode 普通用户输入默认进入 Agent Loop，而不是只进行单轮对话或单步工具调用。
- F2: Agent Loop 每一轮都由模型读取当前上下文、决定输出自然语言回复或请求工具调用。
- F3: Agent Loop 最多执行 12 轮；达到上限仍未自然结束时停止循环，并尽量生成无工具最终总结。
- F4: 当模型自然输出最终回复且不再请求工具时，Agent Loop 正常结束，不额外请求总结。
- F5: ch04 取消 ch03 “同一轮最多一个工具调用”的限制，允许模型在一次响应中返回多个工具调用。
- F6: 多个工具调用按模型给出的原始顺序分批执行；相邻只读工具并发执行，有副作用工具串行执行。
- F7: 只读工具包括读取文件、查找文件和搜索文本；写文件、改文件和执行命令都视为有副作用工具。
- F8: 执行命令工具始终视为有副作用工具，不根据命令内容判断是否只读。
- F9: 并发执行的只读工具结果必须按模型原始工具调用顺序写回上下文。
- F10: 如果同一轮工具调用中出现未知工具，ArtCode 不执行这一轮中的任何工具，直接触发异常停止。
- F11: 已知工具执行失败时，ArtCode 将结构化失败结果回灌给模型，并继续下一轮循环，让模型有机会修正。
- F12: Agent Loop 中有副作用工具自动执行，不再沿用 ch03 的逐次用户确认；安全边界仍依赖允许目录限制、危险命令拦截、超时和结构化错误。
- F13: 用户取消时停止当前整轮 Agent Loop，不再请求模型、不再启动新工具，并尽量取消正在运行的异步工具。
- F14: 流式响应中途出错时，已经显示到界面的半截文本不写入 Conversation Context，本轮停止且不再额外请求总结。
- F15: ArtCode 提供异步事件流，至少覆盖文本增量、工具调用、工具结果、Token 用量和进度事件。
- F16: 流式收集器同时支持两条路径：一边把文本增量实时推给界面，一边收集完整响应用于判断是否结束或是否进入工具执行。
- F17: 如果同一轮模型既输出文本又请求工具，文本可以实时显示给界面，但不作为普通助手消息单独写入上下文。
- F18: 每一轮 assistant 工具调用消息和 tool result 消息都保留在本次运行上下文中，供后续轮次继续推理。
- F19: Token 用量事件只在 Provider 返回真实用量时发出；没有真实用量时跳过，不影响 Agent Loop。
- F20: 进度事件按迭代和工具批次发出，让界面能展示第几轮、收到几个工具调用、正在执行哪一批、是否进入最终总结。
- F21: `/plan 任务描述` 进入只读 Plan Mode，只允许使用读取文件、查找文件和搜索文本工具。
- F22: `/plan` 生成的计划写入本次运行上下文，并保存为本次运行内的最近计划。
- F23: 最近计划只保存在内存中，退出 ArtCode 后不保留。
- F24: `/do` 执行最近计划；`/do 附加说明` 会把附加说明和最近计划一起作为执行目标。
- F25: `/do` 和普通用户输入一样使用全工具 Agent Loop，并受 12 轮上限和相同停止条件约束。
- F26: 普通 Agent Loop、`/plan` 和 `/do` 每一轮都按当前模式携带可用工具列表；异常最终总结不携带工具。
- F27: 异常停止包括达到迭代上限和未知工具；这类停止应尽量生成一次无工具最终总结，说明已完成内容、停止原因和下一步建议。
- F28: 用户取消和流式错误停止后不再请求最终总结，避免取消后继续运行或在错误状态下扩大影响。

## 非功能需求

- N1: Agent Loop 编排逻辑应独立成清晰边界，Runtime 只负责接入用户输入、命令入口和事件消费，避免继续膨胀为大而杂的控制器。
- N2: Agent Loop 事件流应与 TUI 解耦；未来替换界面或增加日志消费者时，不应重写核心循环。
- N3: 事件对象应保持结构化，界面不应依赖拼接后的自然语言文本来判断工具状态、停止原因或进度。
- N4: Agent Loop 不绕过 ch03 已有工具安全边界；允许目录限制、危险命令拦截、命令超时、结果截断和结构化错误仍然生效。
- N5: 本章取消 ch03 的工具执行前用户确认，但不新增权限系统、审批策略、白名单命令或交互式确认。
- N6: 多工具执行必须保持可预测顺序；即使只读工具并发执行，回灌到模型上下文的顺序也必须稳定。
- N7: 用户取消后不应启动新的模型请求或新的工具执行；已经启动的异步工具应尽量取消，无法立即取消时也不应继续推进后续轮次。
- N8: 半截流式文本、取消后的未完成回复和流式错误后的未完成回复不得写入 Conversation Context。
- N9: Plan Mode 的最近计划只保存在本次进程内存中，不落盘、不写入固定计划文件、不做跨会话恢复。
- N10: ch04 不做上下文压缩；多轮工具消息会增加上下文长度，达到模型上下文限制时先以 Provider 错误或结构化停止处理，后续章节再解决压缩。
- N11: ch04 不做长期会话持久化；Agent Loop 的中间消息只存在于本次运行的 Conversation Context。
- N12: Token 用量只展示 Provider 返回的真实数据，不做估算，不把缺失用量视为错误。
- N13: 进度展示应简洁，避免把完整工具输出、长文件内容或大段命令输出直接刷到 TUI。
- N14: Agent Loop 的停止原因应可观测，至少能区分自然完成、迭代上限、未知工具、用户取消和流式错误。
- N15: 单元测试应覆盖停止条件、事件流、流式收集、多工具分批、只读并发、有副作用串行、Plan Mode、`/do` 执行最近计划和上下文写入规则。
- N16: 只要本地配置可用，真实 DeepSeek API 集成测试必须执行；不得因为 API 额度消耗跳过真实测试。

## 不做的事

- 不做权限系统；本章不引入“允许某类操作、禁止某类操作”的细粒度权限配置。
- 不做用户交互式确认；Agent Loop 中写文件、改文件和执行命令不再逐次询问 yes/no。
- 不做命令白名单；`run_command` 一律视为有副作用工具，串行执行。
- 不做上下文压缩；多轮工具消息导致上下文变长的问题留到后续章节。
- 不做长期会话持久化；Agent Loop 中间状态、最近计划和工具结果都只保存在本次运行内。
- 不做计划落盘；`/plan` 生成的最近计划退出 ArtCode 后消失。
- 不做跨会话 `/do`；重启后没有最近计划时，`/do` 应提示用户先执行 `/plan 任务描述`。
- 不做完整任务恢复；用户取消、流式错误或程序退出后，不自动恢复未完成 Agent Loop。
- 不做工具结果完整日志落盘；TUI 只展示摘要，完整工具结果仍只进入本次上下文。
- 不做工具调用审批队列；多个工具调用只按安全性分批执行，不进入人工审核流程。
- 不做 MCP。
- 不做 Hook 系统。
- 不做 Skill 系统。
- 不做多 Provider 工具格式适配；本章继续面向当前 OpenAI-compatible 工具调用格式。
- 不做可视化任务图或状态机 UI；本章只要求事件流能支撑 TUI 展示进度。
- 不做模型 token 用量估算；只有 Provider 返回真实用量时才展示。

## 验收标准

- AC1: 普通用户输入后，ArtCode 默认进入 Agent Loop，并在模型不请求工具时自然结束。
- AC2: Agent Loop 达到第 12 轮仍未自然结束时停止，并生成或尝试生成无工具最终总结。
- AC3: 达到迭代上限时，TUI 能展示明确的停止原因。
- AC4: 模型同一轮返回多个只读工具调用时，ArtCode 能并发执行这些工具。
- AC5: 并发执行的只读工具结果按模型原始工具调用顺序写入 Conversation Context。
- AC6: 模型同一轮返回“只读工具 → 有副作用工具 → 只读工具”时，ArtCode 按原始顺序分成三批执行。
- AC7: `run_command` 即使命令看似只读，也被归为有副作用工具并串行执行。
- AC8: Agent Loop 中写文件、改文件和执行命令不再弹出 ch03 的 yes/no 确认。
- AC9: ch03 的允许目录限制仍然生效；工具访问允许目录外路径时返回结构化错误。
- AC10: ch03 的危险命令拦截仍然生效；明显危险命令不会执行。
- AC11: 已知工具返回结构化失败时，失败结果写入上下文，并继续进入下一轮模型请求。
- AC12: 同一轮工具调用中出现未知工具时，本轮所有工具都不执行，Agent Loop 触发异常停止。
- AC13: 未知工具停止后，ArtCode 尽量生成无工具最终总结，说明停止原因。
- AC14: 用户取消 Agent Loop 后，不再启动新的模型请求或工具执行。
- AC15: 用户取消时，半截流式文本不写入 Conversation Context。
- AC16: 流式响应中途出错时，半截文本不写入 Conversation Context，且不再请求最终总结。
- AC17: Agent Loop 发出结构化事件，能观察到文本增量、工具调用、工具结果和进度事件。
- AC18: Provider 返回真实 Token 用量时，Agent Loop 发出 Token 用量事件。
- AC19: Provider 未返回 Token 用量时，Agent Loop 正常继续，不把缺失用量视为错误。
- AC20: 流式收集器能一边推送文本增量，一边保留完整响应文本。
- AC21: 同一轮模型既输出文本又请求工具时，文本实时显示给界面，但不作为普通 assistant 消息写入上下文。
- AC22: 每一轮 assistant tool_call 消息和 tool result 消息都保存在本次 Conversation Context 中。
- AC23: `/plan 任务描述` 只携带读类工具，不携带写文件、改文件或执行命令工具。
- AC24: `/plan` 可以通过读文件、查找文件和搜索文本生成计划。
- AC25: `/plan` 生成的计划写入 Conversation Context，并保存为最近计划。
- AC26: 最近计划不落盘；重启 ArtCode 后 `/do` 不应找到上一进程的计划。
- AC27: 没有最近计划时输入 `/do`，TUI 提示需要先执行 `/plan 任务描述`。
- AC28: 输入 `/do` 后，ArtCode 使用全工具 Agent Loop 执行最近计划。
- AC29: 输入 `/do 附加说明` 后，附加说明会参与执行目标。
- AC30: 普通 Agent Loop、`/plan` 和 `/do` 每轮都按当前模式携带对应工具列表。
- AC31: 异常最终总结请求不携带工具列表。
- AC32: TUI 能展示第几轮、工具调用数量、工具批次执行和停止原因等进度摘要。
- AC33: TUI 不直接打印完整工具输出，只展示工具结果摘要。
- AC34: 单元测试覆盖 Agent Loop 自然完成、12 轮上限、未知工具停止、用户取消、流式错误、多工具分批、只读并发、有副作用串行、Plan Mode 和 `/do`。
- AC35: 真实 DeepSeek API 集成测试在本地配置可用时执行，并验证至少一个真实的流式 Agent Loop 路径。
- AC36: 端到端验证能完成“用户提出需要读写文件的任务 → Agent Loop 自主读文件 → 自动写文件或改文件 → 继续读取或运行工具验证 → 最终自然语言总结”的完整流程。
- AC37: 端到端验证能完成“`/plan 任务描述` 生成计划 → `/do` 执行最近计划 → Agent Loop 使用全工具完成任务或说明停止原因”的完整流程。
