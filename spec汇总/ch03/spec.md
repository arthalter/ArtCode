# ch03：工具系统 Spec

## 背景

ArtCode 在 ch02 已经具备本地 CLI 多轮流式对话能力，但当前仍是“只能回答问题”的聊天助手：模型不能读取文件、不能修改文件、不能搜索代码，也不能执行本地命令。

ch03 的目标是给 ArtCode 装上第一版工具系统，让模型在回答用户问题时，可以主动请求使用本地工具。ArtCode 负责识别工具调用、执行工具、处理确认、包装结果，并把结果回灌给模型。模型随后基于工具结果生成最终自然语言回复。

这一章完成后，ArtCode 将从“能说话的助手”升级为“能在受控目录内动手干活的本地 Agent 原型”。

## 目标用户

- 正在从零学习 CLI Coding Agent 架构的项目作者。
- 希望理解模型工具调用、工具执行、结果回灌和最终总结流程的新手开发者。
- 希望在本地安全实验目录内体验文件操作、代码搜索和命令执行能力的用户。

## 本章目标

- 让模型可以通过 API 工具调用机制请求本地工具。
- 让 ArtCode 能集中管理、查找和导出工具定义。
- 提供读文件、写文件、改文件、执行命令、找文件、搜文本六个核心工具。
- 将所有工具限制在配置允许的目录内，默认只操作 `/Users/arthalter/Work/ArtCode/实验场`。
- 对写文件、改文件、执行命令等有副作用操作，在执行前请求用户确认。
- 将工具成功、失败、拒绝、超时、截断等情况包装成结构化结果返回给模型。
- 工具执行后再请求一次模型生成最终回复，但这一章不做连续自动工具循环。

## 能力清单

- 模型可以在普通对话中请求使用一个本地工具。
- ArtCode 可以从流式响应中识别并拼接工具调用参数。
- ArtCode 可以把工具调用交给本地工具系统执行。
- ArtCode 可以把工具结果写回本次运行内的对话历史。
- ArtCode 可以基于工具结果再次请求模型生成最终自然语言回复。
- ArtCode 可以在模型不调用工具时继续保持 ch02 的普通流式对话体验。
- ArtCode 可以通过配置文件声明工具允许访问的绝对目录列表。
- ArtCode 可以在默认实验目录不存在时自动创建该目录。
- ArtCode 可以拒绝访问允许目录之外的路径。
- ArtCode 可以在有副作用工具执行前请求用户确认。
- ArtCode 可以把用户拒绝执行包装成模型可理解的工具结果。
- ArtCode 可以对工具执行失败、参数错误、超时和危险命令拦截给出结构化结果。
- ArtCode 可以限制单次工具结果大小，并标记截断状态。

## 功能需求

- F1: ArtCode 提供统一工具抽象，每个工具都能声明自身名称、用途说明、参数约束和执行行为。
- F2: ArtCode 提供工具注册中心，能集中登记工具、按名称查找工具，并导出 OpenAI-compatible function tools 格式的工具列表。
- F3: ArtCode 内置六个核心工具：读取文本文件、写入文本文件、按唯一原文替换修改文本文件、执行本地 shell 命令、按 glob 模式查找文件、按普通文本搜索文件内容。
- F4: ArtCode 通过配置文件声明允许工具访问的绝对目录列表；默认允许目录为 `/Users/arthalter/Work/ArtCode/实验场`，目录不存在时自动创建。
- F5: 所有核心工具都必须受允许目录限制；路径解析后只有落在任一允许目录内才允许访问；命令工具只能在允许目录内作为工作目录执行。
- F6: 写文件、改文件、执行命令属于有副作用工具，执行前必须展示工具名、参数摘要和影响路径或命令，并等待用户确认。
- F7: 用户拒绝工具调用时，ArtCode 将拒绝结果包装成结构化工具结果回灌给模型，而不是直接崩溃或静默忽略。
- F8: 工具执行必须支持超时和错误处理；失败原因以结构化结果返回给模型，包含可理解的错误类别和说明。
- F9: 单次工具结果最多返回 20KB 内容；超出时截断，并在结构化结果中明确标记已截断。
- F10: 文件类工具只处理 UTF-8 文本文件；遇到二进制文件或无法解码内容时返回结构化错误。
- F11: 写文件工具默认拒绝覆盖已有文件；只有模型显式表达覆盖意图时才允许覆盖，且仍需用户确认。
- F12: 改文件工具使用严格原文唯一匹配替换；匹配不到或匹配多次都返回清楚的结构化错误。
- F13: 执行命令工具接收一整段 shell 命令字符串，默认超时 10 秒，并在执行前进行基础危险命令拦截。
- F14: 模型流式响应中的工具调用参数可能分片到达，ArtCode 必须能拼接 JSON 参数碎片并解析成一次完整工具调用。
- F15: 同一轮模型响应最多允许一个工具调用；如果模型请求多个工具调用，ArtCode 将其包装成结构化错误回灌给模型。
- F16: 工具执行完成后，ArtCode 将工具结果写入本次运行内的对话历史，并再次请求模型生成最终自然语言回复；第二次请求不允许继续调用工具。
- F17: TUI 在工具调用过程中展示简洁过程和结果摘要，包括准备调用、等待确认、执行成功、执行失败、结果大小和是否截断。
- F18: ch03 更新系统提示，使模型知道当前可以使用哪些工具、工具边界、单轮最多一个工具调用，以及工具失败后应根据错误信息调整回复。

## 非功能需求

- N1: 工具系统不得绕过允许目录边界；所有路径必须解析成真实绝对路径后再判断是否位于允许目录内。
- N2: 配置中的允许目录只接受绝对路径；相对路径、空字符串和非字符串值都应在启动阶段报错。
- N3: 默认允许目录不存在时应自动创建；如果创建失败，应在启动阶段给出友好错误。
- N4: 工具执行失败、参数错误、权限边界错误、用户拒绝、命令超时和输出截断都不能导致 ArtCode 崩溃。
- N5: 有副作用工具在用户确认前不得执行。
- N6: 执行命令工具不承诺完整沙箱能力；ch03 只提供允许目录工作目录限制、基础危险命令拦截和用户确认。
- N7: 工具调用结果不落盘，只保存在本次运行的 Conversation Context 中。
- N8: 工具结果回灌给模型时不得超过单次 20KB 内容上限。
- N9: TUI 不直接展示完整工具输出，避免大段文件内容或命令输出刷屏。
- N10: 工具注册、工具执行、Provider 工具调用解析、Runtime 编排和 TUI 展示之间职责边界清楚，避免任一层直接承担所有逻辑。
- N11: ch03 保持与 ch02 的纯对话能力兼容；如果模型不调用工具，用户仍能获得正常流式回答。
- N12: ch03 不保存日志文件、不保存完整工具输出文件、不保存会话文件。
- N13: 尽量为每个工具和工具调用流程补充单元测试；无法测试真实 API 行为时，使用模拟流式事件验证解析和编排逻辑。
- N14: 错误提示面向新手，说明问题大概发生在哪里，并避免泄露敏感配置。

## 设计骨架

ArtCode ch03 在 ch02 分层基础上增加工具系统相关边界。

- 配置层：负责读取允许目录配置、校验绝对路径、创建默认实验目录，并向启动状态提供非敏感目录摘要。
- Conversation 层：负责保存用户消息、模型消息和工具结果消息，仍只保存在本次运行内。
- Providers 层：负责把工具定义带给模型，解析流式工具调用参数，并在最终总结请求中关闭继续工具调用能力。
- Tools 层：负责定义统一工具抽象、工具注册中心、允许目录检查、结果包装和六个核心工具。
- Runtime 层：负责协调用户输入、模型首次响应、工具确认、工具执行、结果回灌和最终模型回复。
- TUI 层：负责展示启动状态、工具调用摘要、确认提示、执行摘要、错误提示和最终模型回复。

## 验收标准

- AC1: 启动 ArtCode 后，配置状态能显示 ch03 章节信息和当前允许目录摘要。
- AC2: 缺少工具配置时，ArtCode 使用默认允许目录 `/Users/arthalter/Work/ArtCode/实验场`，并在目录不存在时自动创建。
- AC3: 配置中出现相对允许目录、空允许目录或非字符串允许目录时，启动失败并给出友好提示。
- AC4: 工具注册中心能导出六个 OpenAI-compatible function tools 定义，并能按工具名查找工具。
- AC5: 模型不调用工具时，普通流式对话仍按 ch02 行为正常工作。
- AC6: 模型请求读取允许目录内的 UTF-8 文本文件时，ArtCode 能读取内容、截断超过 20KB 的结果，并把结构化结果回灌给模型。
- AC7: 模型请求读取允许目录外路径时，ArtCode 不读取文件，并把路径越界错误回灌给模型。
- AC8: 模型请求写入新文本文件时，TUI 先展示确认信息；用户确认后文件被写入，用户拒绝时文件不被写入且拒绝结果回灌给模型。
- AC9: 模型请求覆盖已有文件但未显式表达覆盖意图时，ArtCode 返回结构化错误，不覆盖文件。
- AC10: 模型请求按唯一原文修改文本文件时，匹配一次则完成替换；匹配零次或多次则不改文件并返回结构化错误。
- AC11: 模型请求执行 shell 命令时，TUI 先展示命令确认信息；用户确认后命令在允许目录内运行，超过 10 秒返回超时错误。
- AC12: 模型请求明显危险命令时，ArtCode 在执行前拦截，并把危险命令错误回灌给模型。
- AC13: 模型请求按 glob 查找文件时，ArtCode 只返回允许目录内的匹配文件。
- AC14: 模型请求按普通文本搜索代码内容时，ArtCode 只搜索允许目录内的 UTF-8 文本文件，并返回文件路径、行号和匹配行摘要。
- AC15: 模型流式返回 JSON 参数碎片时，ArtCode 能拼接并解析出完整工具调用。
- AC16: 模型同一轮请求多个工具调用时，ArtCode 不执行任何工具，并把“本章只允许一个工具调用”的结构化错误回灌给模型。
- AC17: 工具执行后，ArtCode 再请求一次模型生成最终自然语言回复，且第二次请求不携带可继续调用工具的工具列表。
- AC18: 工具成功、失败、超时、用户拒绝和截断结果都会写入本次运行内 Conversation Context，但不落盘。
- AC19: TUI 展示简洁工具过程和结果摘要，不直接打印完整工具输出。
- AC20: 单元测试覆盖配置解析、允许目录校验、六个工具行为、注册中心导出、工具调用解析、Runtime 单步工具编排和拒绝确认流程。
- AC21: 端到端验证能完成“用户要求写入文件 → 模型调用工具 → 用户确认 → 文件写入 → 模型最终总结”的完整流程。

## Out of Scope

- 不做连续自动 Agent Loop；本章一次用户输入最多触发一次工具执行，再生成一次最终回复。
- 不做同一轮多个工具的正常执行；多个工具调用视为结构化错误。
- 不做 MCP。
- 不做 Hook 系统。
- 不做 Skill 系统。
- 不做长期会话持久化。
- 不做自动上下文压缩。
- 不做完整权限系统。
- 不做完整 shell 沙箱。
- 不做跨目录真实隔离或容器化执行。
- 不做二进制文件读写。
- 不做正则搜索。
- 不做模糊编辑匹配。
- 不做文件 diff 预览。
- 不做工具调用并发。
- 不做运行时通过 Slash Command 修改允许目录。
- 不做命令行参数覆盖允许目录。
- 不做多 Provider 工具格式适配层；ch03 只适配当前 OpenAI-compatible 工具格式。
- 不做工具结果落盘。
- 不做完整工具输出在 TUI 中刷屏展示。
