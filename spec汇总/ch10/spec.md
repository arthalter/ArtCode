# ch10：斜杠命令系统 Spec

## 背景

ArtCode 在前序章节中已经陆续加入 `/help`、`/plan`、`/do`、`/compact`、权限、沙箱、会话和记忆等斜杠命令，但当前实现仍是一套轻量骨架：命令只登记名称与处理行为，帮助文本手工维护，运行主流程通过连续条件分支解释不同结果，界面能力也以具体方法散落在应用流程中。

这种结构在命令较少时可以工作，但继续增加命令会产生三个问题：命令说明与真实行为容易不同步；名称和未来别名的冲突只能在运行时暴露；命令实现直接依赖当前终端渲染方式，难以独立测试或替换界面。同时，斜杠输入与普通对话的边界不够统一，多行斜杠输入可能意外进入 Agent 并消耗 Token。

ch10 的目标是把现有骨架整理为一套集中注册、统一解析、按类型分发、与界面实现解耦的命令系统。用户以斜杠开头的输入必须绕过普通 Agent 分流；本地操作保持快速、确定且不污染对话；需要 AI 的既有命令继续遵守前序章节的 Plan Memory、权限、上下文管理和会话持久化语义。

## 目标用户

- 希望用确定性命令快速查看或调整 ArtCode 当前状态的本地用户。
- 正在学习 CLI Coding Agent 输入分流、命令注册和界面解耦方式的项目作者。
- 后续准备在 Skill 系统中扩展命令来源，但本章只需要稳定内置基础设施的开发者。

## 目标

- 用一个注册中心统一管理命令的身份、说明、分类和执行入口。
- 在进入交互循环前发现所有名称冲突，避免运行到一半才失败。
- 明确区分空输入、普通对话、有效命令和未知命令，任何斜杠命令尝试都不误送 Agent。
- 让命令通过稳定的界面控制边界完成显示、清屏、模式标记和状态刷新，而不依赖具体渲染框架。
- 保持 ch04、ch06、ch08、ch09 已确定的命令行为与安全边界。
- 新增纯视觉清屏和脱敏运行状态查询能力。

## 功能需求

### 注册与元数据

- F1：每条命令集中登记规范名称、可为空的别名集合、简短描述、用法示例、执行类型、可选参数提示、隐藏标记和执行入口。
- F2：命令规范名称和别名使用同一个大小写不敏感的标识空间；任意规范名称、别名或二者之间发生冲突时，系统必须在显示输入提示符前终止启动，并指出冲突标识和相关命令。
- F3：注册中心能够按规范名称或别名查找命令，并为帮助系统提供稳定的命令元数据顺序；本章内置命令不借别名重命名或替代前序章节命令。
- F4：隐藏命令仍可被精确调用，但不出现在普通帮助列表中；本章不预置隐藏命令。

### 输入解析与分流

- F5：空字符串或只含空白的输入立即返回，不调用命令处理行为，也不进入 Agent。
- F6：去除开头空白后不以 `/` 开头的输入保持原文并进入普通 Agent；斜杠出现在句子中间时不触发命令。
- F7：去除开头空白后以 `/` 开头的整段输入必须进入命令解析，不能因命令未知、参数非法或包含换行而回退到普通 Agent。
- F8：命令名在第一个空白字符处结束，按小写形式匹配；其余内容作为参数，保留参数内部换行并去除参数两端空白。
- F9：未命中命令时显示包含原命令名和 `/help` 引导的本地提示，不调用 Provider，不写入 Conversation 或会话日志。
- F10：命令分流位于用户回车后的统一入口；一次输入只能选择命令路径或 Agent 路径之一，不允许两条路径同时执行。

### 执行分类与界面边界

- F11：命令按分发路径分为本地、界面或运行状态、交给 AI 三类；分类作为注册元数据参与帮助展示和分发，不为命令授予额外权限。
- F12：命令实现通过抽象界面控制边界显示消息、清空可见内容、发送 AI 用户消息、设置当前显示模式、读取 Token 与运行状态、请求界面刷新，不直接依赖具体渲染框架。
- F13：普通输入提示符显示 `[DEFAULT]`；执行 `/plan` 请求期间，规划输出显示 `[PLAN]`；规划结束后的下一次输入恢复 `[DEFAULT]`。本章不引入持久 Plan 模式。
- F14：本地和界面状态命令默认不调用普通 Agent，也不把命令文本写入 Conversation 或会话日志；`/compact` 继续允许通过 ch08 摘要流程调用 Provider，但不进入 Agent Loop。
- F15：命令缺少参数、参数非法或本地操作无法完成时显示简明提示并返回输入循环；注册冲突是本章唯一新增的强制启动失败路径。

### 内置命令

- F16：`/help` 不带参数时根据注册元数据展示全部非隐藏命令的名称、描述和用法；带一个命令名时展示该命令的详细元数据；查询未知命令时给出 `/help` 引导。
- F17：`/exit` 和 `/quit` 继续作为两个独立命令退出 ArtCode，不将其中一个改造成另一个的别名。
- F18：`/plan 任务描述` 继续发起一次只读 Plan 请求并保存最近计划；`/do [附加说明]` 继续使用全工具 Agent Loop 执行最近计划；缺少计划或任务描述时保持前序章节提示语义。
- F19：`/compact` 继续触发 ch08 手动压缩，允许在自动线以下或熔断打开时工作，不成为用户消息，也不触发 Agent 工具调用。
- F20：`/permission` 和 `/sandbox` 继续查询或切换 ch06 的进程内权限模式与 Shell 策略；无参数查询、非法值不改状态、关闭 Seatbelt 前确认等既有规则保持不变。
- F21：`/sessions` 继续显示当前会话和最近会话的 ID、标题、消息数、活动时间及使用中标记，不在运行中切换 Conversation；不新增 `/session`。
- F22：`/memory` 继续显示用户级和项目级记忆路径、有效/作废/异常数量及最近更新状态，不显示笔记正文。
- F23：`/clear` 只清空当前终端的可见内容，不删除 Conversation、会话日志、最近计划、长期记忆、Token 状态或其他运行状态。
- F24：`/status` 从本地状态生成一份脱敏快照，至少展示模型、Workspace、当前显示模式、权限模式、Shell/Seatbelt 状态、会话 ID 与状态、当前上下文估算量、上下文窗口上限，以及最近一次 Provider 返回的真实 Token 用量；尚无数据的字段明确显示为不可用。
- F25：内置命令的分发分类固定为：退出、帮助、压缩、会话、记忆和状态属于本地类；清屏、权限和沙箱属于界面或运行状态类；计划和执行最近计划属于交给 AI 类。

## 非功能需求

- N1：命令查找、大小写归一化、冲突检测和帮助排序必须是确定性的，相同注册集合和输入产生相同结果。
- N2：除 `/compact`、`/plan` 和 `/do` 的既有 AI 路径外，斜杠命令不得发起 Provider 请求或增加 Token 消耗。
- N3：未知命令和参数错误不得污染 Conversation、JSONL 会话、Plan Memory、权限状态或长期记忆。
- N4：帮助、状态和错误输出不得显示 API Key、MCP 认证值、指令正文、记忆正文、完整会话内容或其他已知秘密。
- N5：命令基础设施与具体终端渲染框架解耦，注册、解析、帮助生成和分发可以使用假界面独立测试。
- N6：本章不新增第三方运行时依赖，继续满足 macOS 自包含 CLI 的可打包性。
- N7：现有 Agent Loop、Plan Memory、权限规则、Seatbelt、上下文压缩、会话恢复和长期记忆测试必须保持通过。
- N8：单元测试覆盖注册冲突、大小写、别名、隐藏命令、多行参数、未知命令、分流互斥、帮助生成、清屏状态保留、状态脱敏和所有内置命令映射。
- N9：在本地配置可用时执行真实 DeepSeek 集成验证，证明 `/plan → /do` 仍能完成既有两段式工作流，且本地命令不会额外调用 Provider。

## 设计骨架

- **命令定义层**：保存单条命令的完整元数据和执行入口，不处理终端渲染。
- **注册中心**：负责启动登记、统一标识索引、冲突检测、名称解析和帮助枚举。
- **输入解析层**：把原始输入判定为空输入、普通对话或命令调用，并分离规范化命令名与原始参数。
- **命令分发层**：根据注册项和执行类型调用相应行为，统一处理未知命令与用户可修正的参数错误。
- **界面控制层**：向命令暴露最小的显示、清屏、消息发送、模式和状态能力，由当前 TUI 实现。
- **运行状态层**：汇总 `/status` 所需的脱敏字段，并记录最近一次真实 Token 用量，不复制领域模块的可变状态。
- **运行分流入口**：只负责取得输入、调用解析/分发或启动普通 Agent，不再逐条解释每个命令动作。

## Out of Scope

- 不做用户自定义命令、项目级命令配置或运行时动态注册。
- 不做动态生成提示词、自动拼接 Git diff 或新的预设审查命令；`/review` 留给后续章节。
- 不做命令级权限控制、命令白名单或借命令绕过现有权限与 Seatbelt。
- 不做 Tab 补全、参数补全、多候选菜单或自动弹出建议。
- 不新增 `/session`，不把 `/sessions` 改名或设为别名。
- 不把 `/exit` 与 `/quit` 合并为别名关系。
- 不做持久 Plan 模式；普通输入仍是 Default，`/plan` 和 `/do` 保持请求级模式。
- 不做运行中会话切换、恢复或删除；继续通过启动参数选择会话。
- 不做清空 Conversation、重置会话、删除记忆或清除 Token 统计的命令。
- 不把当前 TUI 改造成全屏应用，也不实现持续刷新的底部状态栏。

## 验收标准

- AC1：登记两个仅大小写不同的名称，或让任一名称与别名、别名与别名冲突时，ArtCode 在进入输入循环前失败并指出冲突；合法集合可按名称和别名找到同一注册项。
- AC2：命令元数据能够完整表达名称、零个或多个别名、描述、用法、类型、可选参数提示、隐藏标记和执行行为。
- AC3：空白输入不产生任何调用；普通文本和句中斜杠只进入 Agent；所有首个非空白字符为 `/` 的单行或多行输入只进入命令路径。
- AC4：`/HeLp` 与 `/help` 命中相同命令；Tab、换行或空格都能分隔命令名和参数，参数内部换行保持原顺序。
- AC5：未知斜杠命令显示原命令名和 `/help` 引导，Provider 调用数、Conversation 消息数和会话文件行数均不增加。
- AC6：`/help` 从注册元数据生成列表和单命令详情，新增测试命令后无需修改静态帮助文本即可出现；隐藏命令不进入总览。
- AC7：命令单元测试只使用假界面即可验证显示、清屏、模式、状态和 AI 消息发送，不导入具体渲染框架。
- AC8：执行普通输入时提示符为 `[DEFAULT]`；执行 `/plan` 时输出可观察到 `[PLAN]`；规划完成后再次读取输入时恢复 `[DEFAULT]`。
- AC9：`/exit`、`/quit`、`/plan`、`/do`、`/compact`、`/permission`、`/sandbox`、`/sessions` 和 `/memory` 的前序章节回归测试全部通过。
- AC10：`/clear` 执行后终端旧内容不可见，但对话消息、当前会话、最近计划、长期记忆计数和最近 Token 用量均保持不变。
- AC11：`/status` 在已有和缺失 Token 用量两种情况下都能显示完整脱敏状态；输出不包含测试中植入的 API Key、指令正文或记忆正文。
- AC12：除 `/compact`、`/plan` 和 `/do` 外，逐个执行全部斜杠命令时 Provider 调用数不增加，命令原文也不出现在 Conversation 或 JSONL 中。
- AC13：多行 `/plan` 的完整任务描述进入 Plan 请求，多行未知命令仍只显示本地错误，不回退到普通 Agent。
- AC14：全部单元测试、非 live 集成测试和真实 DeepSeek `/plan → /do` 端到端测试通过，且项目未新增第三方运行时依赖。
