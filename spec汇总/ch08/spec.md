# ch08：上下文管理 Spec

## 背景

ArtCode 当前会持续累积完整对话。工具结果通常占据上下文的大部分空间，而且现有硬截断会直接丢失超出部分。随着 Agent 长时间运行，对话最终可能逼近模型窗口上限，导致请求失败或无法继续工作。

现有系统已经能够接收 API 返回的 Token usage，但尚未利用它持续估算对话规模，也没有工具结果存盘、历史摘要、手动压缩和失败熔断能力。

## 目标用户

- 在本地使用 ArtCode 完成长时间、多轮次编码任务的学习者。
- 希望看懂上下文管理原理，并能观察压缩何时发生、产生什么效果的开发者。

## 目标

- 在用户选择的上下文窗口内支持长时间、多轮次的 Agent 工作。
- 通过轻量预防处理过大的工具结果，并保留可重新读取的完整原文。
- 通过重量兜底压缩较早的历史，同时保留近期工作现场。
- 用户原始消息逐字保留，不由摘要模型改写。
- 自动压缩失败时避免重复调用形成死循环，并保留强制压缩和紧急恢复能力。
- 允许用户主动压缩当前对话。
- 使用 API usage 与字符增量进行近似估算，不引入精确 tokenizer。

## 功能需求

- F1：用户可以在受支持范围内选择当前会话采用的上下文窗口上限，未指定时使用系统提供的默认上限。
- F2：系统以上一次成功 API 请求返回的输入 Token usage 为锚点，只对锚点之后的消息增量和历史变更按字符近似估算。
- F3：没有可用 usage 锚点时，系统能够仅依靠字符近似规则估算本次完整请求规模。
- F4：每次模型 API 请求前，系统先执行工具结果轻量预防，再判断是否需要整体历史重量压缩。
- F5：单个工具结果超过轻量阈值时，系统将完整结果写入当前会话的 Workspace 内部目录，并用固定格式的预览、原始规模和可读路径替换对话内的全文。
- F6：同一轮工具调用产生的结果合计超过聚合阈值时，系统按结果规模从大到小依次存盘，直到对话内保留的本批结果回到阈值以内。
- F7：轻量存盘替代现有的结果硬截断，不能静默丢弃超出旧限制的工具输出。
- F8：模型重新读取存盘结果时必须按行范围分段读取；未指定范围的全文回读不能再次把大结果塞回对话或形成重复存盘循环。
- F9：工具结果文件仅服务当前运行；正常退出时清理当前会话文件，下次启动时清理异常退出遗留的旧会话目录。
- F10：整体历史达到相对上下文窗口计算的自动压缩线时，系统在普通模型请求之前调用当前模型生成结构化摘要，并且不给该请求提供任何工具。
- F11：系统从历史尾部按 Token 预算选择近期原文，同时保证最低消息数量，并保证助手工具调用与其全部工具结果不被切开。
- F12：重量压缩始终保留 System Prompt，并用一份新摘要替换可压缩的较早历史；再次压缩时，上一版摘要与新增旧历史共同折叠为一份新摘要。
- F13：正式摘要固定包含主要请求和意图、关键技术概念、文件和代码段、错误和修复、问题解决过程、所有用户消息、待办任务、当前工作、可能的下一步九个部分。
- F14：被压缩区间中的用户消息必须按原始顺序逐字保留，摘要模型不得改写；如果用户原文自身已超过安全请求能力，系统停止请求并提示开始新会话。
- F15：摘要模型在同一次响应中先输出分析草稿，再输出正式摘要；系统只保存正式摘要并丢弃草稿，缺少有效正式摘要时本次压缩失败且旧历史保持不变。
- F16：压缩完成后，系统插入一条明确的上下文边界消息，要求模型需要文件细节时重新读取实际文件，不得依据摘要猜测代码内容。
- F17：自动摘要连续失败达到熔断条件后，系统暂停普通自动压缩尝试；任意一次压缩成功都会清除连续失败状态。
- F18：历史达到相对上下文窗口计算的强制压缩线时，系统绕过熔断器再次尝试压缩；强制压缩失败后仍允许普通请求继续，由实际超限恢复机制负责最终兜底。
- F19：模型 API 实际返回上下文超限时，系统执行一次不受熔断器限制的紧急压缩，并只自动重试原请求一次；再次失败后停止重试。
- F20：用户可以手动触发压缩；手动压缩绕过自动阈值与熔断状态，只要存在可压缩的旧历史就立即尝试。
- F21：工具结果存盘失败时系统保留完整结果，不退回静默截断；如果继续请求会越过安全边界，则停止请求并向用户报告存盘失败。
- F22：用户能够看到压缩触发原因、压缩前后估算规模、存盘结果数量和当前熔断状态等简洁状态信息。

## 非功能需求

- N1：轻量预防不得调用 LLM，日常大结果处理只产生本地文件写入和近似估算开销。
- N2：任何压缩失败都必须保持原对话可继续检查，不得留下半替换历史或残缺工具调用链。
- N3：相同历史、阈值和 usage 锚点应产生稳定的候选选择顺序与压缩边界，便于测试和排障。
- N4：会话文件必须位于当前 Workspace 的内部目录，路径可以被现有只读文件工具安全访问，且不能借机扩大其他文件访问权限。
- N5：摘要请求不得携带工具定义，也不得接受或执行模型生成的工具调用。
- N6：现有 Normal、Plan、Do 模式以及内置工具、MCP 工具和权限系统在未触发上下文管理时保持原有行为。
- N7：上下文管理状态只属于当前运行，正常退出后不形成跨会话记忆。
- N8：所有自动恢复都有明确次数上限，不能因摘要失败或上下文超限形成无限 API 请求循环。

## 设计骨架

本章能力由六个相互协作的职责组成：

1. **Token 估算**：维护最近一次 API usage 锚点，对新增、删除和替换的消息做字符增量估算，并提供当前请求规模。
2. **结果存盘**：保存完整工具结果、生成稳定预览、管理会话目录，并识别存盘结果的分段回读。
3. **保留区选择**：从历史尾部选择近期原文，维护消息最低数量和工具调用协议边界。
4. **摘要生成**：构造无工具摘要请求，校验草稿与正式摘要边界，并生成九段结构化摘要。
5. **压缩协调**：在请求前依次运行轻量与重量策略，管理自动线、强制线、手动触发、熔断和紧急恢复。
6. **状态展示**：向终端用户报告存盘、摘要、失败、熔断和恢复结果。

## Out of Scope

- 不实现精确 tokenizer，也不引入第三方 tokenizer 作为必需依赖。
- 不使用机器学习、向量检索或自动调参优化压缩策略。
- 不实现文件导入、最近文件固定保留或上下文附件能力。
- 不实现 Skill 系统，也不为尚不存在的 Skill 定义增加保留接口。
- 不实现跨进程的对话恢复、长期记忆或摘要持久化。
- 不自动查询远端模型元数据来推断上下文窗口，窗口上限由本地选项决定。
- 不保证在用户原始消息自身超过可用上下文时继续同一会话。
- 不把工具结果存盘目录作为长期归档或用户文件备份。
- 不改变既有权限语义，不允许摘要过程调用任何本地或远程工具。

## 验收标准

- AC1：未提供窗口选项时系统使用默认上限，提供合法范围内的选项时两条压缩线按同一比例随窗口变化，越界值在启动阶段被拒绝。
- AC2：存在 usage 锚点时只估算锚点后的历史变化；不存在锚点时仍能为完整请求给出可复现的近似值。
- AC3：单个大工具结果被完整写入会话目录，对话中只保留固定预览、规模和有效路径，磁盘文件内容与原始结果一致。
- AC4：同轮多个结果超过聚合限制时按从大到小存盘，处理后保留结果的估算总量不超过限制。
- AC5：超过旧硬截断边界的工具结果仍能从存盘文件读取到完整尾部内容。
- AC6：不带行范围回读存盘文件不会返回全文；按合法行范围读取可以获得对应原文片段且不会形成存盘循环。
- AC7：正常退出删除当前会话结果目录，模拟异常遗留后再次启动能够完成清理。
- AC8：每次普通模型请求前都能观察到轻量检查先于重量检查执行。
- AC9：达到自动压缩线时，在普通模型请求前产生一次不带工具的摘要请求。
- AC10：压缩后 System Prompt、近期预算、最低消息数量和完整工具调用边界均得到保留。
- AC11：正式摘要包含九个固定部分，被压缩区间内的所有用户消息保持原文和原顺序。
- AC12：摘要响应中的分析草稿未进入新历史，只有有效正式摘要被保留。
- AC13：压缩后的边界消息明确要求读取真实文件，并禁止根据摘要补全未知代码。
- AC14：连续摘要失败达到限制后停止普通自动重试，后续普通请求不会产生压缩死循环。
- AC15：达到强制压缩线时即使熔断已打开也会再尝试一次，失败后仍按约定进入普通请求流程。
- AC16：模拟 API 上下文超限时只执行一次紧急压缩和一次原请求重试，再次失败后停止。
- AC17：手动压缩在低于自动线或熔断打开时仍可执行，成功后清除失败状态。
- AC18：工具结果存盘失败不会退回静默截断；继续请求不安全时用户能看到明确失败状态且 API 请求未发送。
- AC19：用户界面可以观察到触发原因、压缩前后估算量、存盘数量和熔断状态。
- AC20：未触发压缩的普通 Agent、工具、MCP、权限和模式回归测试保持通过。
- AC21：真实端到端场景中，对话经过大工具结果存盘、自动摘要和后续模型请求后仍能继续完成任务，并能按需分段读取此前的完整结果。

上下文窗口范围、默认窗口、两条相对压缩线、摘要输出预算、字符换算、轻量阈值、预览大小、近期保留预算、最低消息数、熔断次数和紧急重试次数将在后续技术设计中固定，并写入 `checklist.md` 作为可直接勾选的验收值。
