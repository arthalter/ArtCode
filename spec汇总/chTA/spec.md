# chTA：Agent 系统效率与信息保真评测 Spec

## 背景

ArtCode 已有可运行的 Agent 评测底座，能够调用真实模型、隔离工作区、记录运行轨迹并执行确定性验证。但现有 chTA 只能统计任务是否完成、Token、工具调用、权限拒绝和一次上下文压缩，不能直接证明简历中最关键的三类工程收益：

- MCP 工具延迟加载究竟减少了多少工具描述和模型输入 Token；
- 权限规则复用究竟减少了多少次人工审批请求，同时是否守住危险操作边界；
- 上下文保留修复前后，在真实编码任务中的问题解决能力与信息保真度如何变化。

因此，本阶段为以上三项能力分别建立可重复、可追溯的基线/候选实验。八小时连续会话暂不测试，也不在本阶段简历中保留该数字。

## 目标用户

- 需要为 ArtCode 生成可信简历数据的项目作者；
- 需要复现实验、检查统计口径和追溯原始证据的代码审查者；
- 后续需要比较模型、版本或策略变化的 ArtCode 开发者。

## 总体目标

- 真实测量 MCP 延迟加载、权限审批复用和上下文修复效果。
- 每项结论都给出基线、候选、样本量、原始计数、变化率和证据路径。
- 保证基线与候选只改变被测机制，模型、任务、预算和验证器保持一致。
- 区分官方任务指标、ArtCode 自定义信息保留指标和系统成本指标。
- 不预填目标结果；最终简历只能使用真实运行产生的数据。

## 实验一：MCP 工具延迟加载

### 要回答的问题

在百级 MCP 工具目录中，延迟加载相较于启动时全部注入，减少了多少工具描述 Token 和真实模型输入 Token；工具发现机制是否影响任务完成质量和工具调用成本。

### 能力清单

- 提供同一工具目录的“全部注入基线”和“延迟发现候选”两种运行方式。
- 使用本地、确定性的 MCP 工具目录构造百级工具场景，避免外部服务波动。
- 候选方式初始只暴露工具检索入口，在需要时激活匹配的真实 MCP 工具。
- 已激活工具在当前会话后续轮次中保持可用，但不污染其他会话。
- 两种方式运行相同任务、模型、提示词、预算、重复次数和验证器。
- 记录实际发送给模型的工具定义载荷大小、稳定分词口径下的工具描述 Token 和模型服务返回的输入 Token。
- 同时记录模型轮次、工具调用、检索调用、激活工具数、耗时和任务结果。
- 报告首轮与累计工具描述 Token 降幅、真实输入 Token 变化和质量差异。

### 成功判定

- 两种方式均能完成同一组工具发现与调用任务，或完整记录失败原因。
- 每个百分比都能回溯到基线与候选的原始 Token 数及分词口径。
- 若候选降低 Token 但造成任务失败，报告必须明确展示质量退化。

## 实验二：权限审批复用

### 要回答的问题

面对包含重复副作用操作的固定编码会话，规则复用相较于逐次授权，实际减少了多少次审批请求；自动放行是否只发生在已授权边界内，危险操作是否仍被拒绝。

### 能力清单

- 使用相同的固定工具调用序列分别运行逐次授权基线和规则复用候选。
- 工具调用序列包含三十次正常副作用操作，由五个不同权限目标各重复六次组成。
- 基线每次允许仅对当前操作生效；候选首次批准后允许后续完全匹配的规则自动放行。
- 通过真实权限服务、规则写入器和工具执行链路触发审批，不用权限拒绝数推算审批次数。
- 直接记录审批请求、单次允许、持久允许、规则命中、拒绝和实际副作用。
- 在正常操作序列之外加入危险操作与相似但未授权目标作为负向控制。
- 报告审批请求降幅、规则复用命中数、误放行数、误拒绝数和运行成本变化。

### 成功判定

- 基线和候选执行完全相同的操作序列。
- 审批次数来自审批接口的真实调用事件，而不是工具错误、模型回复或估算值。
- 候选只能自动放行精确命中规则的操作；危险操作与未授权目标不能产生副作用。
- 出现误放行时不得宣称权限效率优化成功。

## 实验三：真实编码任务与信息保留

### 要回答的问题

上下文保留修复前后，ArtCode 在固定 SWE-bench-Live 任务上的官方修复结果和配套信息保留结果分别如何变化；观察到的差异是否来自真实历史版本。

### 能力清单

- 使用 SWE-bench-Live 官方公开任务、官方容器化环境和官方补丁验证口径。
- 固定数据集版本、任务清单、代码版本、模型、预算和运行配置。
- 在正式 Agent 运行前验证任务的 gold patch 在当前环境中可重复通过；无效任务不进入分母并记录原因。
- 首轮使用六个 gold-valid Python 任务组成可运行 pilot，选择过程固定且不可按结果删样本。
- 基线使用上下文保留修复前的真实提交，候选使用引入保留修复的真实提交。
- 两个版本对同一批有效任务生成补丁，并由官方验证器计算 resolved 数和 resolve rate。
- 为同批任务运行独立的信息保留探针，检查原始问题要求、关键约束、相关文件和测试结论在压缩后是否仍可检索。
- 官方 resolve rate 与自定义信息保留率分列报告，不把信息保留率写成 SWE-bench 官方指标。
- 若版本无法构建、任务镜像不兼容或真实 API 中断，报告阻塞范围和已完成证据，不填造数据。

### 成功判定

- 每个计入结果的任务都通过 gold patch 环境预检。
- 每个版本的补丁、官方验证日志、Agent Trace 和信息保留探针均可追溯。
- 版本差异由真实仓库提交界定，不通过人为改坏当前实现制造“修复前”结果。
- 报告分别给出任务解决率和信息保留率，简历表述保持该边界。

## 统一实验协议

- 每项实验使用不可变清单记录任务、版本、模型、配置、重复次数和选择规则。
- 基线与候选在独立工作区运行，避免缓存、权限规则、会话文件和产物相互污染。
- 除被测机制外，基线与候选使用相同输入、预算、超时、验证器和执行顺序。
- 运行失败、超时、API 错误和环境不兼容均作为结果记录，不得静默删除。
- 聚合报告展示原始计数、变化率、样本量、运行状态和不可用原因；重复实验再展示均值、中位数和离散程度。
- 核心效率数字由运行事件、请求载荷或官方验证器计算，不使用 LLM 主观评分。
- 报告保存代码提交、数据集版本、配置指纹和证据文件路径。
- 所有 Trace、配置与报告在落盘和展示前执行敏感信息脱敏。

## 指标边界

| 指标类别 | 允许的来源 | 禁止的替代口径 |
|---|---|---|
| 工具描述 Token | 实际发送的工具定义载荷与固定分词器 | 工具数量或字符数百分比 |
| 模型输入 Token | 模型服务返回的 usage | 工具描述 Token 冒充总输入 Token |
| 审批请求次数 | 权限审批接口调用事件 | 权限拒绝、工具错误或模型轮次 |
| 规则复用次数 | 权限引擎精确规则命中事件 | “总操作数减审批数”的无证据推算 |
| 信息保留率 | 通过的确定性保留探针 / 全部探针 | 最终答对或摘要变短 |
| SWE-bench 解决率 | 官方验证通过任务 / gold-valid 任务 | 自定义单元测试通过率 |

## 非功能要求

- 评测复用 ArtCode 唯一生产 Agent、权限服务、上下文管理和工具执行链路。
- MCP 延迟加载是可在普通会话中启用的真实能力，不实现只为跑分存在的伪路径。
- 实验功能通过显式配置或专用命令启用，不改变普通 CLI 的默认安全行为。
- 本地基准组件应可离线运行；只有真实模型调用和官方数据集获取允许依赖网络。
- 任何插桩不得记录 API Key、Authorization、用户隐私文件内容或未脱敏工具结果。
- 单项实验失败不能阻止其他实验生成报告。
- 评测器“成功运行”与候选“性能更好”分开判断；跑通不等于指标达标。
- 原有 CLI、权限边界、上下文测试和 ch11 评测保持兼容。

## 设计骨架

```text
不可变实验清单
  -> 环境与 gold 预检
  -> 基线/候选隔离运行
  -> 生产链路事件采集
  -> 确定性探针与官方验证
  -> 指标归一化
  -> A/B 聚合
  -> JSON / Markdown / 表格报告
  -> 简历数字映射
```

## Out of Scope

- 暂不测试或宣称八小时以上连续编程会话。
- 不提交或宣称 SWE-bench-Live 官方排行榜成绩。
- 不为了得到预期百分比挑选、删除或重排失败样本。
- 不预设工具 Token 降幅、审批次数降幅或信息保留提升必须达到图片中的数字。
- 不把静态单元测试结果包装成真实模型 A/B 实验结果。
- 不使用人工编辑报告覆盖原始运行数据。
- 不在本阶段建设云端 Dashboard、分布式调度或多人评测平台。

## 完成定义

- 三项实验均有可执行入口、固定清单、隔离基线/候选和机器可读报告。
- MCP 报告能给出真实发送的工具描述 Token 和模型输入 Token 对照。
- 权限报告能给出真实审批请求与规则复用事件，并验证危险操作无副作用。
- SWE-bench-Live 报告能给出 gold-valid 分母、官方解决结果和独立信息保留结果。
- 汇总层输出 JSON、Markdown 和可打开的表格报表，并映射可用于简历的事实句。
- 任意简历数字都能从聚合报告下钻到 Attempt、Trace、验证日志或请求载荷。
- 未实测、不可比或样本不足的指标明确标为不可用，不进入简历。
