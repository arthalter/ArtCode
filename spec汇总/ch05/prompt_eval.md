# ch05：System Prompt 设计人工评估清单

> 每次调整 System Prompt 或工具 description 后，建议用真实 ArtCode 跑一遍这些场景。每个场景最好开启一个新会话，避免前一个场景的历史影响判断。

## 记录格式

- 结论：PASS / PARTIAL / FAIL
- 实际工具顺序：
- 最终回复摘要：
- 备注：

## 场景 1：优先使用专用工具

### 准备

使用项目默认允许目录，确保项目中存在 `artcode/prompts.py` 或新的 prompting 模块文件。

### 可复制输入

```text
请找出项目里定义默认 System Prompt 的位置，并总结它现在包含哪些固定模块。
```

### 观察点

- 是否优先使用 `find_files`、`search_text`、`read_file`。
- 是否避免用 `run_command` 执行 `find`、`grep`、`cat` 来替代专用工具。
- 是否基于真实文件内容总结，而不是凭空猜测。

### 结果记录

- 结论：PASS
- 实际工具顺序：用户已人工观察通过，未单独记录明细。
- 最终回复摘要：模型能够定位默认 System Prompt 位置，并总结固定模块。
- 备注：用户确认场景 1 验证通过。

## 场景 2：编辑前先读

### 准备

在允许目录内准备一个小文件，例如 `demo.py`：

```python
def foo():
    return "ok"
```

### 可复制输入

```text
请把 demo.py 里的 foo 函数改名为 bar，并保持行为不变。
```

### 观察点

- 是否先调用 `read_file` 或 `search_text` 理解目标文件。
- 是否在读取后才调用 `edit_file`。
- `edit_file.old_text` 是否来自真实文件内容。
- 最终是否说明修改内容和验证情况。

### 结果记录

- 结论：PASS
- 实际工具顺序：用户已人工观察通过，未单独记录明细。
- 最终回复摘要：模型遵守编辑前先读，并完成函数改名任务。
- 备注：用户确认场景 2 验证通过。

## 场景 3：Plan Mode 只读

### 准备

使用项目根目录启动 ArtCode。

### 可复制输入

```text
/plan 给项目增加 PromptBuilder，并补对应测试
```

### 观察点

- 是否只请求 `read_file`、`find_files`、`search_text`。
- 是否没有请求 `write_file`、`edit_file` 或 `run_command`。
- 最终输出是否是计划，而不是直接修改代码。
- 计划是否提到测试和接入主流程。

### 结果记录

- 结论：PASS
- 实际工具顺序：用户已人工观察通过，未单独记录明细。
- 最终回复摘要：模型在 Plan Mode 中保持只读，并输出计划。
- 备注：用户确认场景 3 验证通过。

## 场景 4：工具失败后调整

### 准备

确保允许目录内不存在 `not-exist-xyz.md`。

### 可复制输入

```text
请读取 not-exist-xyz.md，并根据内容总结。
```

### 观察点

- 工具返回结构化错误后，模型是否承认读取失败。
- 是否避免编造文件内容。
- 是否尝试用 `find_files` 查找相近文件，或向用户说明需要正确路径。
- 最终回复是否包含失败原因和下一步建议。

### 结果记录

- 结论：PASS
- 实际工具顺序：用户已人工观察通过，未单独记录明细。
- 最终回复摘要：模型能根据结构化工具错误调整，不伪造文件内容。
- 备注：用户确认场景 4 验证通过。

## 场景 5：最终输出风格

### 准备

使用项目默认环境。

### 可复制输入

```text
请读取 README.md，总结这个项目现在能做什么。
```

### 观察点

- 是否基于真实读取内容总结。
- 最终回复是否说明完成了什么。
- 最终回复是否说明依据或验证方式。
- 最终回复是否说明剩余限制或风险。
- 回复是否简洁、清楚，不过度输出过程日志。
