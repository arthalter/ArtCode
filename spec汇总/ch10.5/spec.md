# ch10.5：总结重构 Spec

## 背景

ArtCode 已连续完成十个章节，具备流式对话、Agent Loop、内置工具、权限、macOS Seatbelt、MCP、上下文压缩、会话恢复、长期记忆和斜杠命令等能力。当前版本拥有较完整的自动化回归测试，主要功能大体可用，但实现仍保留明显的章节累积痕迹：同一运行状态存在多个副本，启动入口与运行时重复组装依赖，Agent、工具、持久化和界面协调器承担了过多职责，旧路径策略与新路径策略并存，部分生产路径没有被现有测试覆盖。

代码审查还确认了若干会直接影响用户行为的问题：Thinking 关闭时没有显式关闭服务端默认行为，Thinking 工具调用缺少推理内容续接；只读状态查询会消费一次性恢复提醒；命令取消可能遗留子进程；正式 Workspace 路径策略不能按预期创建多级目录；正常 Agent Loop 仍受固定轮数限制；无效配置可能被静默接受。

ch10.5 不增加新的产品功能，而是对现有能力进行一次总结性整体重构。较新章节和本章确认的规则优先于旧章节的兼容实现。若当前行为没有已确认的问题，也没有明显更简洁的实现方式，则默认保留；若兼容层、边缘功能或安全附加能力会显著妨碍代码简洁、可读和内聚，则允许删减，但不能破坏主要使用流程。

## 目标用户

- 希望继续扩展和学习 ArtCode，但需要先恢复代码可读性与可维护性的项目作者。
- 使用 ArtCode 完成本地编码任务，希望核心交互、工具、会话和上下文能力保持可用的本地用户。
- 需要通过大量自动化与手工场景观察 Coding Agent 在协议、取消、恢复、压缩、权限和外部工具故障下表现的学习者。

## 目标

- 建立职责内聚、依赖方向清楚、单一状态源驱动的应用架构。
- 修复已经通过代码审查和最小复现确认的协议、状态、路径、进程与配置问题。
- 保持普通对话、Plan/Do、工具、MCP、上下文、会话和长期记忆等主要功能可用。
- 删除不再承担真实产品职责的旧章节兼容代码、重复状态、无效类型和分散常量。
- 使只读操作保持无副作用，使后台能力与当前回复隔离，使资源在正常退出和异常启动失败时都能可靠回收。
- 建立覆盖正常路径、复杂边界、故障注入、真实 API、真实进程和真实 MCP 的大规模测试体系。
- 在开发结束后提供与实际代码一致的最终架构图、测试证据和手工验收清单。

## 功能需求

### 启动、组装与运行状态

- F1：应用只有一个生产依赖组装入口，负责读取启动参数和配置、创建各运行组件并明确注入依赖；运行时对象不得再次隐式创建另一套生产组件。
- F2：需要关闭的网络客户端、MCP 会话、会话日志、上下文临时文件和沙箱资源由统一生命周期管理；启动中途失败、正常退出和用户中断都必须按确定顺序清理已经创建的资源。
- F3：权限模式、Shell 策略、显示模式和最近 Token 用量等进程内可变状态各自只有一个权威来源，其他组件只读取同一状态或不可变快照，不通过强制修改冻结对象保持同步。
- F4：启动状态与运行状态由运行环境汇总，配置模块只描述配置本身，不保存会话、记忆、沙箱或界面状态的默认副本。
- F5：状态查询只读取并展示脱敏快照，不消费恢复提醒、不修改对话、不改变压缩状态、不写入会话，也不触发普通模型请求。

### 配置与 DeepSeek Provider

- F6：主配置顶层字段和每个已知配置段都采用明确字段集合；发现未知字段时启动失败，并一次列出当前层级的全部未知字段。
- F7：MCP Server 配置容器存在但类型错误时启动失败，不得静默当作未配置；单个 Server 内部的非法字段继续产生可定位到该 Server 的错误。
- F8：当前目标模型以经官方核验的 DeepSeek V4 Flash 版本为基线，默认上下文窗口采用该模型公开支持的完整窗口；用户仍可显式配置较小的受支持窗口，压缩阈值按窗口比例变化。
- F9：Thinking 关闭时请求必须显式关闭 Thinking；Thinking 开启时只使用统一的高推理强度，不再提供无实际差异的多档选择。
- F10：Provider 必须接收流式推理内容，并在带工具调用的 Assistant 消息中保存和续接协议要求的推理内容；连续多轮 Thinking 工具调用不得因缺失协议字段失败。
- F11：Provider 内部以结构化事件表达文本、推理内容、工具调用、Token 用量和完成状态，不能依靠松散字典在多个层级重复猜测字段。
- F12：Provider 在应用生命周期内复用网络连接资源；错误分类继续对用户隐藏认证秘密，并使用真实配置位置而非旧章节文件名提供提示。
- F13：普通对话继续使用当前已经验证可用的流式对话协议；本章不迁移 Provider 主协议。

### Agent Loop、请求组装与上下文

- F14：正常交互的 Agent Loop 不设置默认工具迭代上限，只在模型自然完成、用户取消、请求失败或明确不可继续时停止；测试和自动化调用方仍可显式设置有限上限。
- F15：请求组装接收全部显式输入并返回完整模型请求，不在估算、状态查询或重组过程中消费一次性业务状态。
- F16：恢复间隔提醒只在真正发送的首次适用模型请求中出现一次；状态估算、压缩前试组装和失败于发送前的准备过程不得让提醒消失。
- F17：模型因输出长度限制结束时，系统保留模型实际生成的文本，不添加“未完成”标记、不自动继续、不创建特殊会话状态；用户可以根据可见上下文要求继续。
- F18：用户提交的每条消息始终作为独立的真实用户消息逐字保存，不得删除、替换、合并或由摘要模型改写。
- F19：上下文压缩只能折叠较早的 Assistant、Tool 和内部 System 历史；摘要可以引用用户消息，但必须由程序重新注入对应用户原文和顺序。
- F20：本章不为超大用户输入增加额外预检、回滚或专用状态机；当不可压缩的用户原文使请求超过服务能力时，允许 Provider 返回失败，用户可以新建会话。
- F21：请求准备、上下文估算、轻量工具结果存盘、重量摘要和超限重试形成清晰边界；Agent Loop 只负责推进状态，不直接拥有这些策略的全部细节。
- F22：取消或流式错误产生的半截 Assistant 文本继续只显示在终端，不写入 Conversation 和会话存档；已确定的工具调用必须得到结构化的取消或中断结果以保持协议完整。

### 工具、路径、权限与沙箱

- F23：每个注册工具提供统一的来源与副作用类别，Plan 模式、并发批次和权限判断使用同一份工具能力信息，不在多个模块维护重复的工具名称集合。
- F24：未知工具、模式不允许的工具、非法参数、审批拒绝和执行异常都转换为稳定的结构化工具结果；一个工具实现抛出未预期异常时不得让同批次已完成结果丢失。
- F25：文件读取、写入和编辑在准备阶段与真正执行前都验证当前路径边界，避免审批期间路径或符号链接变化使实际目标偏离已展示目标。
- F26：写入新文件时自动创建 Workspace 内不存在的父目录；Workspace 内合法符号链接继续可用，指向 Workspace 外或敏感范围的路径仍被拒绝。
- F27：文件覆盖和精确编辑继续保持现有可观察语义：默认不覆盖已有文件，精确编辑要求原文唯一匹配，失败时不产生部分修改。
- F28：Shell 命令在独立进程组中运行；超时和用户取消都直接终止整个进程组并等待回收，不允许父进程结束后留下后代进程继续运行。
- F29：权限规则、一次性审批、永久允许和永久禁止继续保持现有行为；本章只收敛职责和状态来源，不重新设计用户可见的权限模型。
- F30：命令沙箱当前继续禁止网络访问，网络域名代理和细粒度网络权限只作为未来可能项；当前实现应集中表达“全部禁止”，不得把网络假设散落到各工具。

### MCP、命令与界面

- F31：MCP Server 的配置、连接、工具适配、调用和关闭继续保持独立边界；单个 Server 不可用、工具名冲突或调用失败不得破坏内置工具和其他正常 Server。
- F32：MCP 工具继续经过人工确认并以可能有副作用的外部工具处理；Plan 模式信息必须通过当前执行上下文传递，不能读取执行器上的隐藏可变标记。
- F33：斜杠命令继续通过注册、解析和分发基础设施工作；本章不增加新命令，只修复状态查询副作用和运行状态来源。
- F34：终端界面只负责输入、显示和人工确认；业务服务通过稳定的展示事件或界面边界与其交互，不依赖具体终端渲染细节。

### 会话、恢复与长期记忆

- F35：每条已经确定的真实 User、Assistant 和 Tool 消息继续同步追加到人类可读的会话日志；内部请求提醒、摘要草稿和运行状态不得伪装成真实用户记录。
- F36：恢复时遇到一条完整但损坏的独立记录，跳过该记录、显示警告并继续恢复其前后的其他有效记录；遇到不完整尾部时截断尾部；遇到会破坏工具调用协议的记录时只保留安全前缀。
- F37：恢复、显式新建、按 ID 恢复、会话锁和过期清理继续保持现有主要行为；两个进程不得并发追加同一会话。
- F38：长期记忆只接收自然完成轮次的不可变副本，并在后台串行处理；记忆超时、模型失败、解析失败、存储失败或关闭取消都不得改动 Conversation、当前回复和 Agent 控制流。
- F39：长期记忆的解析、调度、用户级与项目级存储、索引重建和状态报告保持可分别测试的边界；本章不改变长期记忆的用户可见分类和文件格式。

### 迁移与验收

- F40：重构采用横向分波方式推进，每一波都先建立行为测试，再修改相关实现，并在进入下一波前运行相关集成测试和全部回归测试。
- F41：旧章节兼容路径、章节编号产品文本、重复状态、无调用方类型和失效常量在其替代路径验证完成后删除，不长期保留新旧两套实现。
- F42：自动化测试覆盖单模块逻辑、跨模块链路、故障注入、随机化输入、真实 DeepSeek、真实 Seatbelt、真实子进程和真实 MCP；测试数量只设最低门槛，不因达到数量停止补充高价值场景。
- F43：最终验收包含一组由用户亲自执行的复杂手工场景，覆盖启动、配置、Thinking、长循环、取消、超时、路径、权限、沙箱、Plan/Do、MCP、上下文、恢复、并发会话和长期记忆。
- F44：重构结束后，文档、测试说明和架构图必须反映实际代码，不继续使用旧章节实现作为当前事实来源。

## 非功能需求

- N1：优先级依次为代码简洁与可读、职责内聚与解耦、后续修改便利、主要功能可用，安全强化和边缘兼容位于其后。
- N2：新增抽象必须消除真实重复、隐藏状态或依赖倒置问题；不得为尚未实现的功能预建通用框架。
- N3：核心业务状态必须可从单一来源追踪，读取操作默认无副作用，跨层通信使用明确数据而非读取其他对象的私有可变字段。
- N4：模块依赖从交互与应用编排指向核心边界和基础设施接口，不允许基础设施反向控制终端界面或 Agent 主循环。
- N5：相同输入、配置、持久文件和模拟外部响应产生确定性结果，方便复现、回归和故障定位。
- N6：后台记忆、MCP、摘要和资源清理的失败采用局部隔离，不得把非关键失败升级为当前正常回复失败。
- N7：测试代码可以显著多于生产改动，但应优先使用参数化、共享夹具和故障注入构造器表达场景，避免复制粘贴形成新的测试维护负担。
- N8：关键协议、会话、路径、权限和进程逻辑必须覆盖成功、拒绝、超时、取消、损坏、重试、恢复和清理分支。
- N9：存在可运行的真实 API 或真实本地集成时必须执行，不因 DeepSeek 调用成本跳过；真实测试失败必须与确定性测试失败分开报告。
- N10：每个迁移波次结束时项目保持可启动且全部已承诺行为有测试证据，不进行一次性推倒重写。
- N11：本章原则上不增加生产运行时依赖；若测试需要新增纯测试依赖，必须只服务可重复的高价值验证，并在技术设计中明确说明。
- N12：不得修改、覆盖或清理与本次重构无关的用户工作区改动和未跟踪文件。

## 设计骨架

本章目标架构由以下职责协作，具体类型、接口和文件组织在后续技术设计中确定：

1. **启动与生命周期**：集中读取参数和配置、组装依赖、启动资源，并统一处理正常与异常关闭。
2. **交互与运行协调**：接收用户输入、分发命令或普通请求、维护脱敏运行快照，并把领域事件交给终端展示。
3. **Agent 状态机**：保存单次 Agent 运行的循环状态，协调模型请求和工具结果，不承担全部请求准备与持久化细节。
4. **请求准备与上下文管理**：以无隐藏副作用的方式组装请求，执行估算、工具结果存盘、历史摘要和有限超限恢复。
5. **Provider 边界**：封装 DeepSeek 流式协议、Thinking 续接、结构化事件、连接复用和错误映射。
6. **工具执行与权限**：依据统一工具能力信息完成批次规划、审批、规则处理、执行和结果归一化。
7. **Workspace 文件与进程执行**：集中处理路径边界、符号链接、父目录创建、命令进程组和沙箱策略。
8. **会话服务**：负责日志追加、目录扫描、锁定、恢复、截断和过期清理。
9. **长期记忆服务**：接收已完成轮次，在独立后台队列中更新笔记和索引，并只报告结果。
10. **MCP 基础设施**：管理外部 Server 生命周期，并通过统一工具边界向 Agent 暴露能力。

## Out of Scope

- 不实现 Skill 系统，也不为尚不存在的 Skill、插件市场或热加载预建接口。
- 不实现网络域名代理、动态域名授权、网络白名单或交互式网络放行；命令沙箱继续使用全部禁止策略。
- 不迁移 Provider 主协议，也不同时维护两套普通对话请求流程。
- 不增加重复工具调用检测、启发式死循环判断或自动停止 Claude 风格的工具循环。
- 不自动续写因输出长度限制结束的模型回复，也不新增“回复不完整”业务状态。
- 不为超大用户输入实现专用预检、回滚、分片上传或跨会话自动搬运。
- 不实现新的斜杠命令、会话分支、会话合并、全文搜索、云同步或远程长期记忆。
- 不重新设计权限产品模型，不把安全强化、加密、本地密钥库或跨平台沙箱作为本章主目标。
- 不把终端改造成全屏应用，不新增 Web、桌面图形界面或后台服务。
- 不保留仅为了旧章节测试而存在、生产流程已经不用的兼容实现。

## 验收标准

- AC1（F1～F5）：从正常启动、启动中途失败、用户退出和用户取消四条路径观察，生产依赖只组装一次，已创建资源均被关闭；切换 Shell 或权限状态后所有展示与执行读取同一结果；连续执行状态查询不改变 Conversation、恢复提醒、压缩状态和 Provider 调用计数。
- AC2（F6～F8）：主配置或嵌套配置含多个未知字段时启动一次列出全部字段；错误类型的 MCP 容器明确失败；默认窗口与当前目标 DeepSeek 模型公开窗口一致，显式较小合法窗口使全部相对阈值同比变化。
- AC3（F9～F13）：Thinking 关闭请求可观察到显式关闭参数；开启时只使用统一强度；真实 DeepSeek 连续 Thinking 工具调用可完成后续轮次且续接消息包含服务端要求的推理内容；认证、上下文和流中断错误不泄露秘密。
- AC4（F14～F17）：正常 Agent 在超过旧轮数后继续运行；显式测试上限仍能确定停止；多次请求估算和状态查询不消费一次性提醒；长度结束只保存已生成文本且没有自动续写请求。
- AC5（F18～F22）：经过多次工具结果存盘和重量摘要后，全部用户消息仍以独立记录保持原文、数量和顺序；超大用户输入没有新增特殊状态；取消和流错误不保存半截 Assistant 文本，工具协议仍保持完整。
- AC6（F23～F24）：新增测试工具只声明一次能力信息即可同时参与模式过滤、批次规划和权限判断；未知、禁用、非法、拒绝和异常工具调用都形成结构化结果，同批次其他结果保持可观察。
