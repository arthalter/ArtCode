# ch06：权限系统 Spec

## 背景

ArtCode 已经具备六种本地工具、Agent Loop、Plan Mode、多工具调用和基础路径限制，但现有安全能力仍然比较分散：文件工具依赖允许目录，命令工具主要依赖简单危险命令检查，Agent Loop 中的有副作用操作默认自动执行，缺少统一、持久且可解释的权限决策流程。

这会产生几个问题：模型可能在用户没有明确授权时修改文件或执行命令；旧的“实验场与多个允许目录”设计混淆了 ArtCode 自身位置和被辅助项目的位置；Shell 命令仅靠应用层正则无法形成可靠隔离；用户作出的允许或拒绝决定也不能沉淀为后续可复用的权限规则。

ch06 将建立一套面向 macOS 本地学习场景的纵深权限系统。系统区分 ArtCode Home 与 Workspace，通过硬安全边界、三层权限规则、权限模式和 HITL 共同决定每次工具调用是否允许、询问或拒绝；Shell 命令获得允许后，根据当前策略进入 macOS Seatbelt 沙箱或在用户明确承担风险的无沙箱环境中执行。

## 目标用户

- 希望学习 Coding Agent 权限系统和纵深防御设计的项目作者。
- 希望控制 ArtCode 读取、修改和执行范围的本地用户。
- 希望在自动化效率与人工控制之间切换不同信任程度的用户。

## 本章目标

- 区分 ArtCode 自身数据目录和当前被辅助项目的 Workspace。
- 让五个文件工具只能访问 Workspace，并防止相对路径和符号链接逃逸。
- 为敏感配置、权限规则、Skills 和安全策略建立不可绕过的访问边界。
- 对明显危险的终端命令进行硬拒绝。
- 使用 macOS Seatbelt 对 Shell 进程及其子进程实施操作系统级强制限制。
- 提供 Default、Edit、Full 三档工具权限模式。
- 保持 Plan 为独立的硬只读运行状态。
- 加载用户级、项目级和本地级三层 YAML 权限规则。
- 让显式规则优先决定权限，未匹配时由当前权限模式兜底。
- 对最终结果为 ASK 的调用暂停 Agent Loop，并由用户决定本次或后续同类操作。
- 支持在当前运行中切换权限模式和 Shell 沙箱策略。
- 使用真实 macOS 环境验证 Seatbelt 的读写、网络、子进程和超时边界。

## 功能需求

### Workspace 与应用数据

- F1：ArtCode 区分自身应用数据位置与当前被辅助项目的 Workspace，两者互不混用。
- F2：ArtCode 使用稳定的用户级应用目录保存主配置、用户权限和 Skills。
- F3：Workspace 默认取启动 ArtCode 时的当前目录，并允许通过启动参数指定其他已有目录。
- F4：Workspace 在一次运行中保持固定，不支持运行期间切换。
- F5：相对文件路径和命令工作目录统一以 Workspace 为基准。
- F6：旧的多允许目录和默认实验场机制被移除，实验场只作为 Workspace 中的普通目录。

### Plan 独立限制

- F7：Plan 是独立的 Agent 运行状态，不属于 Default、Edit、Full 三种权限模式。
- F8：Plan 状态下只向模型提供读取文件、查找文件和搜索文本三种只读工具。
- F9：Plan 状态下的写文件、编辑文件和执行命令请求直接拒绝，规则和 HITL 不能解除限制。
- F10：Plan 状态下的只读操作仍须通过路径和敏感路径检查，不能因只读身份绕过硬安全边界。

### 路径与敏感资源

- F11：五个文件工具只能访问 Workspace 本身及其子路径。
- F12：所有路径在判断前转换为规范的真实路径，并在解析符号链接后检查是否仍位于 Workspace。
- F13：创建新文件时检查其真实父目录，防止通过不存在路径或符号链接写出 Workspace。
- F14：查找和搜索过程中遇到指向 Workspace 外部的符号链接时不得继续访问外部目标。
- F15：敏感路径同时禁止模型读取和写入，并且不能被权限规则、权限模式或 HITL 放行。
- F16：敏感范围至少覆盖主配置、三层权限文件、Skills、安全命令规则、Seatbelt 模板和生成策略。
- F17：ArtCode 主进程中的可信配置加载器、规则加载器和本地规则写入器可以执行各自必要的敏感文件操作。
- F18：普通文件工具不能利用可信内部通道访问敏感路径。

### 危险命令检查

- F19：终端命令执行前必须经过不可绕过的危险命令检查，命中后立即拒绝。
- F20：危险命令规则由 ArtCode 内置安全文件提供，不能被三层权限规则修改或关闭。
- F21：危险命令至少覆盖系统根目录破坏、磁盘格式化、磁盘设备写入、根目录权限破坏、fork bomb 和远程脚本管道执行。
- F22：危险命令额外覆盖 macOS 磁盘工具、macOS 磁盘设备、Workspace 整体删除和 Git 强制清理。
- F23：Workspace 相关的危险目标根据当前 Workspace 动态判断，而不是依赖固定绝对路径。
- F24：危险命令检查只提供明确高危行为的基础拦截，不承诺完整理解或覆盖所有 Shell 语法变形。

### 三层权限规则

- F25：权限规则分为用户级、项目级和本地级三个来源。
- F26：规则文件不存在时视为空规则，已存在但无法读取、解析或校验时停止当前操作。
- F27：每次工具调用前重新读取三层规则，使用户手动修改后无需重启即可生效。
- F28：单条规则采用 `工具名(pattern)` 匹配表达式，并产生 ALLOW、ASK 或 DENY。
- F29：规则解析使用第一个左括号和最后一个右括号确定外层边界，允许 pattern 内部包含括号。
- F30：文件路径 pattern 匹配相对于 Workspace 的路径，并统一使用正斜杠。
- F31：文件路径 Glob 使用精简 Gitignore 语义，区分单层通配与跨目录通配。
- F32：路径和命令匹配均区分大小写。
- F33：命令 pattern 匹配去除首尾空白后的完整命令文本，不改写命令内部内容。
- F34：读取、写入和编辑规则匹配目标文件路径；查找和搜索规则匹配实际扫描的起始路径；命令规则匹配完整命令。
- F35：同一层级中最后一条匹配规则覆盖此前匹配规则。
- F36：三个层级分别计算有效规则，任一层级的有效 DENY 都使整体结果为 DENY。
- F37：没有有效 DENY 时，本地级结果优先于项目级，项目级结果优先于用户级。
- F38：三层规则均未匹配时，才由当前权限模式或 Shell 策略提供默认决策。
- F39：规则文件错误统一指出出错文件和原因，不使用旧快照、不退回模式、不进入 HITL。
- F40：启动阶段发现已有规则文件错误时，ArtCode 启动失败。

### 权限模式与 Shell 策略

- F41：ArtCode 提供 Default、Edit、Full 三种工具权限模式。
- F42：Default 对只读工具默认允许，对文件写入与编辑默认询问。
- F43：Edit 对只读、写入和编辑默认允许。
- F44：Full 对五个文件工具默认允许。
- F45：三种权限模式本身不产生 DENY，显式拒绝来自硬安全边界或权限规则。
- F46：ArtCode 独立提供沙箱自动执行、沙箱确认执行和无沙箱确认执行三种 Shell 策略。
- F47：Shell 策略优先决定未匹配规则的命令默认结果，工具权限模式不改变该结果。
- F48：沙箱自动执行在规则未匹配时默认允许命令进入 Seatbelt。
- F49：沙箱确认执行和无沙箱确认执行在规则未匹配时默认进入 HITL。
- F50：显式 ALLOW、ASK、DENY 规则优先于权限模式和 Shell 策略的默认结果。
- F51：无沙箱状态不提供自动执行的默认行为，切换到无沙箱前必须得到一次明确确认。
- F52：权限模式和 Shell 策略通过 Slash Commands 在当前进程中切换，不跨会话保存。
- F53：不带参数的模式命令只展示当前状态、含义和可选值。

### HITL 人在回路

- F54：权限决策最终为 ASK 时暂停当前 Agent Loop，等待用户决定。
- F55：审批界面展示工具、目标、Workspace、当前模式、Shell 策略和 ASK 来源。
- F56：用户可以选择仅本次允许、仅本次禁止、以后允许或以后禁止。
- F57：仅本次决定不修改规则文件；长期决定生成当前目标的精确匹配规则。
- F58：长期规则只写入本地级权限文件，不自动扩大为目录或命令类别通配。
- F59：本地级存在完全相同的 match 时，更新其 action 并将其移动到规则列表末尾。
- F60：规则写回只保证 YAML 含义和顺序，不保证保留原有注释与排版。
- F61：长期规则写入失败统一视为规则文件错误，停止当前操作。
- F62：HITL 中按下取消键会取消整个 Agent Loop，不写规则，也不继续处理后续工具。
- F63：同一轮多个工具按模型原始顺序独立判断和审批，一个工具被拒绝不自动取消其他工具。

### Seatbelt 执行

- F64：只有获得最终 ALLOW 的命令才能启动 Shell。
- F65：Seatbelt 仅约束 Shell 进程及其派生子进程，ArtCode 主进程继续作为可信控制器。
- F66：Seatbelt Profile 由内置模板结合当前 Workspace、专用临时目录和敏感路径动态生成。
- F67：Profile 在启动时生成一次并完成最小可运行自检，当前进程内重复使用。
- F68：Seatbelt 允许读取普通文件系统资源，但敏感路径禁止读写。
- F69：Seatbelt 只允许写入 Workspace 和本次运行的专用临时目录。
- F70：Seatbelt 禁止全部网络访问，包括外网、局域网和本机回环网络。
- F71：Seatbelt 允许执行程序和创建子进程，所有派生进程继承相同限制。
- F72：Shell 使用固定的 macOS zsh 环境，并避免主动加载用户 Shell 配置。
- F73：Shell 只继承运行所需的安全环境变量，不能获得主进程中的 API Key、Token、密码等秘密变量。
- F74：命令超时后终止整个进程组，防止派生进程继续运行。
- F75：Seatbelt 不存在、自检失败、策略生成失败或命令启动失败时，不允许自动降级为普通 Shell。
- F76：无沙箱策略只保留应用层防御和人工授权，不承诺阻止所有 Shell 绕过。

### 界面与动态提醒

- F77：启动界面展示 Workspace、权限模式、Shell 策略和 Seatbelt 自检状态。
- F78：每轮动态提醒向模型说明 Workspace、Plan 状态、权限模式、Shell 策略和主要安全边界。
- F79：动态提醒只用于减少无效工具请求，不能代替执行层的强制权限判断。
- F80：权限拒绝、规则错误、沙箱错误和用户决定以结构化结果回灌模型，使模型能够调整后续行动。

## 非功能需求

- N1：权限系统采用失败关闭原则，任何无法确定的硬安全状态都不能自动执行工具。
- N2：硬安全边界、规则决策、模式兜底、HITL 和工具执行之间职责清晰，不能把全部逻辑堆入 Agent Loop 或 TUI。
- N3：权限判断必须发生在工具产生副作用之前，拒绝或取消后不得留下部分写入。
- N4：规则合并和匹配结果必须确定，同样的三层文件、工具调用和运行状态始终得到相同结果。
- N5：每次调用重新加载三层 YAML 的开销应保持轻量，不得明显阻塞正常工具执行。
- N6：本地规则写入应避免产生半写文件，写入完成前不能破坏上一份合法规则。
- N7：规则文件错误必须可定位到具体文件和具体原因，但不得泄露敏感内容。
- N8：主配置、环境变量和工具结果均不得向模型或终端输出完整 API Key、Token、密码等秘密。
- N9：Workspace 和敏感路径检查必须基于规范真实路径，不能只做字符串前缀比较。
- N10：权限决策不得依赖 System Prompt 或模型自觉遵守，提示词只用于解释边界。
- N11：HITL 暂停期间不得启动目标工具、后续工具或新的模型请求。
- N12：用户取消后应及时停止当前 Agent Loop，并尽量取消已启动的异步工作。
- N13：只读工具原有的并发能力可以保留，但多个 HITL 询问不能同时出现在终端。
- N14：Shell 命令必须在固定超时和结果大小限制内执行，超时、输出截断和失败均返回结构化结果。
- N15：Seatbelt 策略必须对 Shell 整个进程树生效，不能只限制最外层 Shell。
- N16：沙箱开启时，规则 ALLOW、Full 模式和用户本次允许都只能授权进入 Seatbelt，不能授权脱离沙箱。
- N17：沙箱不可用或失败时不得静默降级；无沙箱执行只能来自用户主动选择的 Shell 策略。
- N18：无沙箱模式必须明确展示风险，但本章不承诺该模式下的绝对安全。
- N19：本章仅支持 macOS，并以本机实际存在的 Seatbelt 能力作为运行前提。
- N20：由于 `sandbox-exec` 属于已弃用系统接口，相关实现应集中隔离，避免其细节扩散到规则引擎、Agent Loop 和文件工具。
- N21：权限模式、Shell 策略和 Workspace 必须在启动界面及查询命令中保持可观测。
- N22：单元测试应覆盖规则解析、Glob、三层合并、模式兜底、Plan 限制、路径逃逸、敏感路径和 HITL 决策。
- N23：集成测试应覆盖多工具顺序审批、规则热重载、规则文件错误、取消传播和结构化结果回灌。
- N24：真实 macOS 测试必须证明 Seatbelt 的允许与拒绝行为实际生效，不能只比较生成的 Profile 文本。
- N25：旧的实验场默认目录和多允许目录机制应被完整移除，不能同时保留两套 Workspace 边界。
- N26：改造后仍须兼容 ch05 的多轮 Agent Loop、Plan、Do、Prompt Cache 和临时动态提醒行为。

## 不做的事

- 不支持 Linux、Windows 或其他平台的权限沙箱。
- 不实现 Docker、容器、虚拟机或完整操作系统隔离。
- 不接入 macOS Keychain。
- 不支持运行期间切换 Workspace。
- 不提供图形化权限规则编辑器。
- 不实现完整 Shell AST 解析器。
- 不承诺危险命令正则覆盖所有编码、变量、引号或命令替换变形。
- 不承诺无沙箱模式下的绝对安全。
- 不提供网络访问白名单；Seatbelt 状态下统一禁止网络。
- 不允许模型直接修改用户级、项目级或本地级权限文件。
- 不允许权限规则解除 Plan、危险命令、路径沙箱或敏感路径限制。
- 不支持用规则临时解除 Seatbelt 限制。
- 不在运行期间更换或编辑 Seatbelt 模板。
- 不允许 Seatbelt 失败后自动降级为普通 Shell。
- 不跨会话保存当前权限模式和 Shell 策略。
- 不保存长期权限审计日志。
- 不自动迁移项目根目录中的旧配置文件。
- 不兼容旧的多允许目录和默认实验场配置。
- 不保留 HITL 重写 YAML 前的注释、空行、引号和缩进格式。
- 不自动把“以后允许/禁止”扩大为目录级或命令类别通配规则。
- 不支持多个 Workspace 同时运行在同一个 ArtCode 会话中。
- 不提供完整资源隔离，不承诺绝对限制 CPU、内存、磁盘占用或进程数量。
- 不把 ArtCode 主进程整体放入 Seatbelt；只隔离 Shell 进程树。
- 不让文件工具通过 Seatbelt 代替应用层路径和敏感路径检查。

## 验收标准

### ArtCode Home 与 Workspace

- AC1：首次启动时，`~/.artcode/` 和 `~/.artcode/skills/` 不存在则自动创建。
- AC2：ArtCode 只从 `~/.artcode/config.yml` 读取主配置，不再读取 Workspace 中的旧 `artcode.yaml`。
- AC3：旧配置中的 `tools.allowed_dirs`、默认实验场目录和对应运行逻辑已移除。
- AC4：未提供启动参数时，启动命令所在目录成为 Workspace。
- AC5：使用 `artcode --workspace <目录>` 时，指定目录成为 Workspace。
- AC6：指定的 Workspace 不存在或不是目录时启动失败，并且不自动创建。
- AC7：启动后不能通过 Slash Command 切换 Workspace。
- AC8：相对文件路径和默认命令工作目录都以 Workspace 为基准。
- AC9：命令显式指定的工作目录只有解析后仍位于 Workspace 才能使用。

### Plan 与工具模式

- AC10：Plan 状态下，模型请求中只暴露 `read_file`、`find_files`、`search_text`。
- AC11：Plan 状态下，`write_file`、`edit_file`、`run_command` 不能被规则或 HITL 放行。
- AC12：Plan 状态下读取 Workspace 外路径仍然被拒绝。
- AC13：Default 模式下，三个只读文件工具无规则匹配时为 ALLOW，两个文件写工具为 ASK。
- AC14：Edit 模式下，三个只读文件工具和两个文件写工具无规则匹配时均为 ALLOW。
- AC15：Full 模式下，五个文件工具无规则匹配时均为 ALLOW。
- AC16：权限模式自身不会产生 DENY。
- AC17：ArtCode 每次启动时使用 Default 权限模式。
- AC18：`/permission default`、`/permission edit`、`/permission full` 能切换当前进程的权限模式。
- AC19：不带参数执行 `/permission` 时显示当前模式和三个可选值，不修改状态。
- AC20：退出并重新启动后，权限模式恢复为 Default。

### Shell 策略

- AC21：ArtCode 支持 Sandbox Auto、Sandbox Ask、Unsandboxed Ask 三种 Shell 策略。
- AC22：ArtCode 每次启动时使用 Sandbox Auto。
- AC23：Sandbox Auto 在规则未匹配时使 `run_command` 获得 ALLOW，并在 Seatbelt 中执行。
- AC24：Sandbox Ask 在规则未匹配时使 `run_command` 进入 HITL，用户允许后仍在 Seatbelt 中执行。
- AC25：Unsandboxed Ask 在规则未匹配时使 `run_command` 进入 HITL，用户允许后在普通 Shell 中执行。
- AC26：执行 `/sandbox off` 前展示风险并要求确认，用户拒绝时保持原状态。
- AC27：系统不存在“关闭 Seatbelt 并默认自动执行命令”的策略。
- AC28：不带参数执行 `/sandbox` 时显示当前策略和三个可选值，不修改状态。
- AC29：退出并重新启动后，Shell 策略恢复为 Sandbox Auto。
- AC30：显式规则命中时采用规则结果；只有 NO_MATCH 才使用当前 Shell 策略。

### 路径沙箱与敏感路径

- AC31：五个文件工具访问 Workspace 内普通路径时能够正常工作。
- AC32：五个文件工具访问 Workspace 外路径时，在产生读取或写入之前被拒绝。
- AC33：包含 `..` 的路径解析后越出 Workspace 时被拒绝。
- AC34：Workspace 内符号链接指向 Workspace 外部时，文件工具不能访问真实目标。
- AC35：Workspace 内符号链接指向 Workspace 内部时，可以按真实目标正常访问。
- AC36：创建新文件时，如果真实父目录位于 Workspace 外则被拒绝。
- AC37：`find_files` 和 `search_text` 不跟随符号链接扫描 Workspace 外内容。
- AC38：`~/.artcode/config.yml`、三层权限文件和 `~/.artcode/skills/` 对模型工具均不可读取和写入。
- AC39：内置危险命令规则、Seatbelt 模板和生成后的 Profile 对沙箱 Shell 不可读取和写入。
- AC40：权限规则、Full 模式和 HITL 的“仅本次允许”均不能解除敏感路径限制。
- AC41：可信主进程可以读取主配置和规则，并能在长期 HITL 决定时更新本地级权限文件。

### 危险命令

- AC42：命中危险命令正则的 `run_command` 在规则读取和模式判断前直接 DENY。
- AC43：三层规则中的 ALLOW 不能放行已命中危险正则的命令。
- AC44：黑名单能够拦截递归删除系统根目录。
- AC45：黑名单能够拦截磁盘格式化和直接写磁盘设备。
- AC46：黑名单能够拦截根目录递归权限修改和 fork bomb。
- AC47：黑名单能够拦截明显的远程脚本管道执行。
- AC48：黑名单能够识别 macOS 的 `diskutil`、`newfs_*` 和 `/dev/disk*`、`/dev/rdisk*` 高危操作。
- AC49：黑名单能够阻止递归删除当前 Workspace 整体。
- AC50：黑名单能够阻止约定的 Git 强制清理和整体回滚操作。
- AC51：危险命令拒绝结果包含稳定规则标识和面向用户的原因。
- AC52：内置危险规则文件格式错误时 ArtCode 启动失败。

### 三层 YAML 规则

- AC53：用户级规则读取自 `~/.artcode/permissions.yml`。
- AC54：项目级规则读取自 `<workspace>/.artcode/permissions.yml`。
- AC55：本地级规则读取自 `<workspace>/permissions.local.yml`。
- AC56：任一权限文件不存在时视为空规则，不导致启动或调用失败。
- AC57：已存在的权限文件包含非法 YAML、非法字段、未知工具、非法 action 或非法表达式时，能指出对应文件并停止操作。
- AC58：运行期间修复规则文件后，下一次工具调用重新读取并使用修复后的内容。
- AC59：规则采用有序 `rules` 列表，每项包含 `match` 与 `action`。
- AC60：`match` 使用 `工具名(pattern)`，`action` 只接受 `allow`、`ask`、`deny`。
- AC61：表达式以第一个 `(` 和最后一个 `)` 为外层边界，pattern 内部可以包含括号。
- AC62：缺少外层括号、工具名为空或 pattern 为空时判定规则文件错误。
- AC63：文件规则使用 Workspace 相对路径和 `/` 分隔符。
- AC64：`*` 不跨越目录，`**` 可以跨越任意目录层级，并支持 `?` 与字符集合。
- AC65：路径和命令 Glob 均区分大小写。
- AC66：命令匹配前只去除首尾空白，不修改内部空格、换行或 Shell 符号。
- AC67：同一层级多条规则匹配时，列表中最后一条成为该层有效规则。
- AC68：任意层级的有效 DENY 都使整体结果为 DENY，其他层级 ALLOW 不能覆盖。
- AC69：没有有效 DENY 时，本地级有效结果覆盖项目级和用户级，项目级覆盖用户级。
- AC70：三层均为 NO_MATCH 时，才使用权限模式或 Shell 策略。
- AC71：规则解析失败时不使用上一次快照、不退回模式，也不进入 HITL。

### HITL

- AC72：最终结果为 ASK 时，目标工具尚未开始执行。
- AC73：审批界面展示工具名称、目标或命令、Workspace、权限模式、Shell 策略和 ASK 来源。
- AC74：选择“仅本次允许”后执行当前工具，但不修改规则文件。
- AC75：选择“仅本次禁止”后拒绝当前工具，但不修改规则文件。
- AC76：选择“都允许”后执行当前工具，并在本地级文件写入精确 ALLOW 规则。
- AC77：选择“都禁止”后拒绝当前工具，并在本地级文件写入精确 DENY 规则。
- AC78：HITL 自动生成的文件规则只匹配当前目标路径，不自动扩大到父目录。
- AC79：HITL 自动生成的命令规则只匹配当前完整命令，不自动增加通配符。
- AC80：本地级存在相同 match 时，旧项被更新并移动到列表末尾，不留下重复项。
- AC81：规则写回后语义与顺序正确，即使原注释和排版发生变化。
- AC82：本地规则写入失败时指出文件和原因，停止当前工具，不执行本次决定。
- AC83：HITL 中按 `Ctrl+C` 取消整个 Agent Loop，不写规则，也不继续处理其他工具。
- AC84：同一轮多个工具按原始顺序逐个审批，一个被拒绝后其他工具仍可继续判断。
- AC85：工具拒绝、权限文件错误和用户决定以结构化结果回灌模型。

### Seatbelt

- AC86：启动时创建本次进程专用临时目录。
- AC87：启动时根据内置模板生成一份包含 Workspace、临时目录和敏感路径的 Profile。
- AC88：启动时通过最小命令验证 Profile 可解析并能启动程序。
- AC89：系统不存在 `sandbox-exec`、Profile 生成失败或最小自检失败时 ArtCode 启动失败。
- AC90：自检失败时展示简短原因和 Profile 路径，不输出完整策略文本。
- AC91：Sandbox Auto 与 Sandbox Ask 使用同一份已验证 Profile。
- AC92：沙箱 Shell 可以读取普通系统文件和 Workspace 普通文件。
- AC93：沙箱 Shell 不能读取或写入任何敏感路径。
- AC94：沙箱 Shell 可以写入 Workspace 中的普通路径。
- AC95：沙箱 Shell 可以写入本次进程的专用临时目录。
- AC96：沙箱 Shell 不能写入 Workspace 与专用临时目录之外的位置。
- AC97：沙箱 Shell 不能访问外网、局域网、localhost 或回环地址。
- AC98：Shell 创建的子进程继承相同的读取、写入和网络限制。
- AC99：`run_command` 使用固定 `/bin/zsh -f -c` 执行命令。
- AC100：Shell 环境包含必要的安全变量，并将 `TMPDIR` 指向专用临时目录。
- AC101：Shell 环境不包含 API Key、Token、Secret、Password 等主进程秘密变量。
- AC102：命令超过固定时限后，Shell 及其整个进程组被终止。
- AC103：运行期间 Profile 丢失、损坏或 `sandbox-exec` 启动失败时，当前命令停止且不降级。
- AC104：退出 ArtCode 时尽量清理专用临时目录和生成的 Profile。
