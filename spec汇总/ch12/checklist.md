# ch12：Skill 系统 Checklist

> 所有条目在实现阶段逐项勾选。每项都以可运行测试、可检查的模型请求或可观察的 CLI 行为验证，不以阅读代码替代验证。

> 验证记录（2026-08-25）：新增 Skill 边界/流程定向测试均通过；真实模型的自然语言加载与斜杠执行各 1 项通过；不依赖网络的完整回归为 1625 项通过、39 项取消选择、1 项预期失败。此前全量（含真实环境）为 1653 项通过、3 项失败；失败均为 SWE-bench 环境未就绪、Grok 未返回 DeepSeek 专属推理增量、以及中转服务一次读取超时。

> 已知预期失败：独立 Skill 的 `history_turns: 0` 会使临时子对话丢失主会话的基础系统提示；对应测试已以 `xfail` 固化，待最小修复后再勾选。

## Skill 文件与目录发现

- [x] 项目级目录固定为 `<workspace>/.artcode/skills/`，用户级目录固定为 `~/.artcode/skills/`，内置来源是包内只读目录。（验证：在三处创建临时目录，检查发现器记录的来源与优先级。）
- [x] 根目录中的单个 `*.md` 文件可被识别为 Skill。（验证：写入带 YAML frontmatter 和正文的 Markdown，目录包含对应名字。）
- [x] 目录型 Skill 只以 `<技能目录>/SKILL.md` 为入口，目录下的模板、示例、脚本、参考文档不会成为额外 Skill。（验证：同一目录写入 `SKILL.md`、`template.md`、`example.md`、`helper.py`，目录只列出一个 Skill。）
- [x] frontmatter 只接受 `name`、`description`、`tools`、`mode`、`history_turns`、`model` 六个字段。（验证：逐一注入未知字段，候选得到含路径和原因的解析诊断。）
- [x] `name` 是可安全映射为 `/<name>` 的小写标识，非法字符、空白、空名和内置命令冲突均被拒绝。（验证：使用合法和非法名字分别发现，断言目录与诊断。）
- [x] `description` 是非空的一句话文本，`tools` 是无重复字符串列表。（验证：空值、多行、非列表、重复工具名分别产生诊断。）
- [x] `mode` 只允许共享或独立；独立 Skill 省略 `history_turns` 时为 `0`，指定值为非负整数；共享 Skill 声明 `history_turns` 时被跳过。（验证：参数化解析测试逐项检查值与错误。）
- [x] `model` 缺省时不声明模型，存在时必须是非空文本。（验证：缺省、有效、空字符串、非字符串四种输入。）
- [x] Skill 正文被原样保存为 SOP，不进行 `{{input}}`、`${...}` 或任何其他占位符替换。（验证：正文含这些文字时，激活请求中仍保留原文本。）
- [x] 同一来源中两个 Skill 声明同名时，发现明确报错，不能依赖扫描顺序。（验证：交换创建顺序后均得到同类重复身份错误。）
- [x] 同名的项目、用户、内置 Skill 按项目 > 用户 > 内置覆盖。（验证：三层分别提供不同说明和正文，目录及加载结果只使用项目版本；移除后依次降级。）
- [x] YAML 损坏、错误 UTF-8、不可读文件、符号链接或目录越界只跳过该候选，不影响其他有效 Skill。（验证：同目录放置一个坏文件和一个好文件，好文件仍能加载且诊断含坏文件路径。）

## 启动校验、目录提示与两阶段加载

- [x] 进程启动时，所有有效 Skill 的 `tools` 都与当前普通工具和可用 MCP 工具进行校验。（验证：Skill 白名单写入不存在名字时，Bootstrap 失败且指出 Skill 路径和工具名。）
- [x] 未知白名单工具是启动阻断错误，不会进入交互式会话。（验证：启动 fake TUI，确认没有调用 `read_input`。）
- [x] 首次普通模型请求只包含每个有效 Skill 的 `name` 和 `description`，不包含任何完整 SOP。（验证：捕获 Provider 请求并搜索目录名、说明、SOP 独有标记。）
- [x] 未激活目录型 Skill 的模板、示例、脚本和参考文档正文不出现在首次请求。（验证：为每份附属资源植入唯一标记并扫描 Provider 请求。）
- [x] 系统工具名为 `load_skill`，它总是在模型可调用工具集合中。（验证：分别在无激活、单 Skill、多个 Skill 场景捕获工具定义。）
- [x] `load_skill` 只接受目录中的 Skill 名字，不接受任意文件路径或未知名字。（验证：路径、`..`、空值、未知名字返回结构化错误且激活集合不变。）
- [x] 自然语言请求中模型调用 `load_skill` 后，下一次模型请求出现对应完整 SOP。（验证：使用脚本化 Provider 先返回加载工具调用，再断言下一次请求消息。）
- [x] 激活 Skill 后完整 SOP 位于 `<active-skills>` 系统边界中，并在基础提示之后、会话历史之前。（验证：检查请求消息顺序和内容。）
- [x] 激活 SOP 在普通请求、只读估算、自动压缩后的重组和紧急重试中都持续出现。（验证：对四条请求路径安装请求捕获器，逐一搜索唯一 SOP 标记。）
- [x] 完整 SOP、目录型资源正文和认证信息不会写入会话日志、状态面板或普通 Skill 诊断。（验证：植入秘密和正文标记后扫描输出与持久化文件。）

## 激活状态、热更新与清空

- [x] 成功加载 Skill 后，激活集合包含其定义快照和激活顺序。（验证：连续加载两个 Skill，断言运行快照顺序固定。）
- [x] 每次开始新的用户请求前检查 Skill 文件变化；保存有效新正文后下一次请求无需重启即使用新 SOP。（验证：首次请求后编辑文件，再次请求捕获新标记。）
- [x] 已激活 Skill 被改成无效格式后，当前会话仍使用最后有效 SOP，并显示可定位诊断。（验证：先激活、再损坏、再请求；断言旧标记仍在且诊断出现。）
- [x] 未激活 Skill 在热更新后变得无效时不进入目录，不影响其他已发现 Skill。（验证：更新一个未激活文件为坏 YAML，其他目录项和请求保持可用。）
- [x] 已激活 Skill 被删除时，不再接受新的加载，但当前会话保留最后有效版本直到清空。（验证：删除入口后验证目录与激活请求，随后清空并确认 SOP 消失。）
- [x] `/clear` 后已激活 Skill、一次性模型覆盖和组合白名单均被清除，其他既有 `/clear` 状态语义不改变。（验证：比较清空前后的 Conversation、会话、计划、权限、记忆、Token 状态与 Skill 状态。）

## 工具白名单与安全边界

- [x] 无激活 Skill 时，普通模型请求工具集合与 ch12 前完全一致，额外仅有 `load_skill`。（验证：对比基线工具名集合。）
- [x] 单个激活 Skill 时，模型只看到该 Skill `tools` 中列出的普通工具与 `load_skill`。（验证：捕获请求工具定义并做精确集合比较。）
- [x] 多个激活 Skill 时，普通工具集合是所有白名单的交集，而不是并集。（验证：两个白名单只有一个共同工具，捕获请求后只剩该工具及 `load_skill`。）
- [x] 空白名单 `tools: []` 时模型仍可调用 `load_skill`，但看不到任何普通工具。（验证：捕获请求工具名并精确断言。）
- [x] ToolExecutionService 拒绝模型伪造的、未展示或不在交集内的普通工具调用。（验证：直接注入工具调用，结果为 `tool_not_allowed`，工具实现未执行。）
- [x] Plan 模式在 Skill 白名单允许写工具时仍只暴露既有只读工具。（验证：在 Plan 请求中声明写工具，工具集合和执行结果均遵守只读限制。）
- [x] Skill 白名单不能改变权限审批、路径限制、危险命令检查、Seatbelt 或 MCP 审批。（验证：在允许的白名单内分别触发拒绝路径、危险 shell、沙箱网络和 MCP 审批场景。）
- [x] `load_skill` 不受白名单影响，但不能借此读取任意文件、执行脚本或授予其他工具权限。（验证：尝试非法参数和能力包脚本路径，确认均失败且权限状态不变。）

## 用户入口与共享执行

- [x] 用户输入 `/<Skill 名>` 时，尚未激活的合法 Skill 在同一轮被定位、加载并执行。（验证：fake TUI 输入短命令，观察一次执行周期内有激活 SOP 和最终回复。）
- [x] 用户输入 `/<Skill 名> 附加要求` 时，附加要求作为当前用户要求与 SOP、已有对话一起发送，不替换或改写 SOP。（验证：请求中同时存在附加文字与完整 SOP 原文。）
- [x] 已激活 Skill 的短命令可在帮助信息中显示名称、说明和用法。（验证：加载后执行 `/help` 和 `/help /<Skill 名>`，检查可见条目。）
- [x] 非法名字或与内置命令冲突的 Skill 不能覆盖现有命令。（验证：构造冲突定义，`/help`、`/clear` 等内置命令仍按原行为执行。）
- [x] 不存在的 `/<Skill 名>` 保持既有未知命令提示，不会向模型发送普通用户消息。（验证：捕获 Provider 调用数为 0。）
- [x] 共享模式使用主 Conversation、主 Agent Loop 和既有会话持久化。（验证：完成共享 Skill 后，主会话同时含用户请求、工具记录和最终回复。）
- [x] 共享 Skill 执行成功后继续保持激活，下一轮普通用户请求仍看到 SOP 与收窄工具集合。（验证：执行短命令后发送普通消息，捕获第二轮请求。）

## 独立模式与模型覆盖

- [x] 独立模式的 `history_turns: 0` 不带入任何旧对话轮次；`N` 只带最近 N 个完整用户轮次及关联 Assistant/Tool 记录。（验证：构造多轮含工具调用历史，检查子 Conversation 内容与顺序。）
- [x] 历史选择不拆开 Assistant 工具调用和对应 Tool 结果。（验证：边界落在工具轮次中间时，子 Conversation 要么带完整单元，要么全部不带。）
- [ ] 独立子对话拥有基础系统提示、当前激活 Skill、组合白名单、权限、路径政策和 Seatbelt。（验证：捕获子请求并分别验证消息、工具、权限拒绝与沙箱结果。）
- [x] 独立子对话不绑定主会话日志、长期记忆观察者或主上下文压缩状态。（验证：执行后比较主会话文件、记忆队列、压缩锚点和子过程记录。）
- [x] 独立模式完成时，主历史仅新增原始用户请求和最终总结，不含子对话的中间文本、工具调用或工具原始输出。（验证：为子过程植入标记，扫描主 Conversation 和 JSONL。）
- [x] 独立子对话取消、模型失败或工具失败时，主会话保持可继续，并接收可诊断的失败摘要。（验证：逐一注入失败，随后发送主会话普通请求并得到正常响应。）
- [x] Skill 声明 `model` 时，仅该次共享或独立执行的 Provider payload 使用该值。（验证：连续捕获 Skill 执行和后续普通请求的 payload model。）
- [x] 指定模型被 Provider 拒绝时显示明确失败，后续普通请求恢复会话默认模型，绝不静默切换其他模型。（验证：注入模型错误并比对下一次 payload。）

## 目录型资源边界

- [x] 加载目录型 Skill 时只读取并激活 `SKILL.md` 正文，同时可观察到模板、示例、脚本、参考文档的资源清单。（验证：捕获加载结果，正文只含入口 SOP，清单列出资源相对路径。）
- [x] 目录型资源不会自动运行、不会自动整体注入上下文，也不会扩大工作区文件访问范围。（验证：资源内写入执行探针和唯一文本；加载后无进程执行、请求不含文本、路径政策未改变。）

- [x] 不创建或激活任何 Skill 时，普通对话、Plan/Do、命令、会话恢复、长期记忆、上下文压缩、MCP 和权限测试均保持通过。（验证：运行对应现有单元与集成测试集。）
- [x] 启动阶段一份损坏 Skill 不阻止另一份有效项目 Skill 被自然语言加载；完整 SOP 只从第二轮开始出现。（验证：脚本化 Provider 的两轮端到端测试。）
- [x] 用户在项目 Skill 目录新增一个共享 Skill 后，输入 `/<Skill 名> 对当前任务的附加要求`，系统不重启即可执行，后续普通追问仍受该 SOP 与白名单约束，`/clear` 后恢复默认工具。（验证：fake TUI + Provider 捕获全流程。）
- [x] 用户激活一个独立 Skill 后，系统带入指定完整历史轮次运行临时 Agent，只将最终总结回流主会话；随后主对话可继续正常工作。（验证：端到端比较主/子 Conversation、事件和下一次普通请求。）
