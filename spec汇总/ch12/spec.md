# ch12：Skill 系统 Spec

## 背景

ArtCode 已具备 Agent Loop、工具调用、上下文管理、会话与命令系统，但用户每次希望 AI 执行相似工作时，仍需要重复解释步骤、约束和工具边界。现有的项目指令适合描述整个项目的长期规则，不适合封装可单独启用、可复用且有明确执行范围的操作流程。

ch12 建设本地 Skill 系统：用户或模型可以按需选择一份可复用的 Markdown SOP，让它在当前任务中持续生效，并依据 Skill 声明收窄模型可见工具。系统必须避免在启动时把全部 Skill 正文塞入上下文，也不能因为一个写坏的 Skill 阻断其他可用 Skill。

## 目标

- 用独立 Markdown 文件把可复用 AI 操作封装为本地 Skill。
- 启动时只提供 Skill 名称和一句说明；真正使用时才按需加载完整 SOP。
- 同时支持用户以斜杠命令明确使用 Skill，以及模型根据自然语言需求自行选择加载。
- 让激活 Skill 的完整 SOP 在后续每轮请求中稳定生效，并通过工具白名单约束模型可见能力。
- 支持共享当前对话与独立子对话两类执行方式。
- 支持项目、用户、内置三层来源与无需重启的热更新。

## 功能需求

### Skill 定义与能力包

- F1：单个 Skill 使用“YAML frontmatter + Markdown 正文”的文件格式。frontmatter 描述唯一身份、一句话说明、可见工具白名单、执行模式、独立模式历史轮数和可选模型；正文是加载后提供给模型的 SOP。
- F2：Skill 正文不支持或要求任何模板占位符语法。当前对话、用户的本次附加要求和 SOP 由运行时直接组合后交给模型。
- F3：系统同时支持单文件 Skill 与目录型 Skill。目录型 Skill 具有明确入口 Markdown，模板、示例、辅助脚本和参考文档可随入口组成一个能力包；这些附属资源不得被误识别为独立 Skill，也不得自动执行或自动全部注入上下文。
- F4：ch12 只提供通用 Skill 机制，不预置任何具体 Skill 样板，也不为特定名字写专门的执行逻辑。

### 发现、优先级与诊断

- F5：Skill 从项目、用户、内置三层目录发现；项目层优先于用户层，用户层优先于内置层。同名 Skill 只保留优先级最高的版本。
- F6：单个候选 Skill 的格式、元信息或入口解析失败时，系统跳过该候选并提供可定位诊断，其他 Skill 仍可发现和使用。
- F7：同一层中存在重复身份时，系统明确报错，不能依赖不稳定的扫描顺序选择其中之一。
- F8：每个已发现 Skill 的工具白名单在启动时校验。白名单出现不存在的普通工具时，启动必须失败，不能静默忽略或延迟到执行时才发现。

### 两阶段加载与激活状态

- F9：启动后，模型只获得已解析 Skill 的名称和一句说明；完整 SOP、附属资源正文和未激活的工具约束均不得进入初始模型请求。
- F10：系统提供一个始终可用的系统级加载能力。模型可根据目录信息调用它，读取并激活指定 Skill 的完整 SOP；该加载能力不受任何 Skill 工具白名单影响。
- F11：激活一个或多个 Skill 后，所有激活 Skill 的完整 SOP 必须固定放在后续模型请求的环境上下文显著位置；即使请求重建、上下文估算、压缩或重试，仍持续存在。
- F12：用户可直接输入 `/<Skill 名>` 使用尚未激活或已激活的 Skill。该输入在同一轮完成定位、加载（如需要）和执行；成功加载的 Skill 同时成为后续可见的斜杠短命令。
- F13：用户以自然语言提出需求时，模型可根据启动时可见的名称和说明自行选择并调用系统级加载能力。
- F14：Skill 成功执行后保持激活，直到用户清空当前对话。清空对话必须同时清空已激活 Skill，避免 SOP 与旧任务意外带入新任务。

### 工具白名单与安全边界

- F15：没有激活 Skill 时，普通工具保持既有可见性和执行边界。Skill 激活后，模型只看到当前激活 Skill 白名单共同允许的普通工具；多个激活 Skill 的白名单取交集。
- F16：系统级加载能力始终保留在模型可调用工具中，不受上述交集影响。
- F17：工具白名单只收窄模型可见工具，不绕过既有 Plan 模式、权限审批、路径限制、危险命令检查、沙箱或 MCP 安全边界。

### 两种执行模式

- F18：共享模式在当前主对话和现有 Agent Loop 中执行。请求、工具调用、过程与最终回复均按既有语义留在主对话历史。
- F19：独立模式创建临时子对话执行。子对话带入基础系统指令、当前已激活 Skill、该 Skill 声明数量的最近完整对话轮次，以及本次用户要求；不带入未被选择的更早历史。
- F20：独立模式结束时，只将该子对话的最终总结写回主对话；子对话完整过程不混入主历史，也不作为可恢复的主会话记录保存。
- F21：Skill 可选声明专用模型。专用模型只影响该 Skill 的本次执行；不可用时明确失败，不静默替换为其他模型，也不改变当前会话的默认模型。

### 热更新与兼容性

- F22：用户修改、增加、覆盖或删除 Skill 文件后，无需重启 ArtCode；下一次新请求前，系统应重新发现并使用最新有效版本。
- F23：运行期间新版本不合法时，系统保留当前最后一个有效版本并显示诊断，不能让运行中的会话崩溃；下一次冷启动仍按启动校验规则处理。
- F24：Skill 名称可安全映射为斜杠短命令；非法名称或与既有命令冲突时必须明确拒绝，不能覆盖既有命令行为。
- F25：现有普通对话、Plan/Do、命令、会话、记忆、上下文管理、工具权限、MCP 和沙箱行为在未使用 Skill 时保持兼容。

## 非功能要求

- N1：两阶段加载必须可观测：可从模型请求或事件确认启动阶段只含目录信息，激活后才含完整 SOP。
- N2：Skill 发现、覆盖、加载、激活、热更新和白名单决策必须有确定性结果，不依赖文件系统返回顺序。
- N3：系统不得把用户级认证信息、项目外的私密文件或完整未激活 Skill 正文写入状态展示、会话、诊断或模型请求。
- N4：独立子对话的工具执行继续经过与主对话相同的权限、路径、沙箱和取消处理；子对话失败不得损坏主对话。
- N5：启动阶段与热更新阶段的诊断要区分“可跳过的单文件解析问题”和“必须阻止启动的未知白名单工具”，并给出来源路径与原因。
- N6：在不激活 Skill 的情况下，新增能力不得增加普通模型请求中的完整 Skill SOP 或改变普通工具集合。

## 设计骨架

系统由五个协作部分组成：

1. **Skill 发现与目录层**：扫描三级来源，解析单文件或能力包入口，按优先级生成确定的目录快照与诊断。
2. **Skill 状态层**：维护当前目录快照、已激活 Skill 和最后有效版本；负责清空与热更新时的状态切换。
3. **加载与命令入口**：向模型提供轻量目录和系统级加载能力，并把自然语言加载、斜杠直达和已激活短命令收敛到同一激活流程。
4. **请求组装层**：每轮将激活 SOP 固定放入环境上下文，并按当前白名单生成模型可见普通工具，同时保留系统级加载能力。
5. **执行编排层**：根据共享或独立模式选择主对话或临时子对话；独立模式负责选取完整历史轮次、隔离执行并回流最终总结。

## 不做的事

- 不提供 Skill 市场、联网下载、发布、分发服务或社区目录。
- 不做 Skill 的版本号、版本对比、升级、依赖解析或回滚管理。
- 不实现正文参数模板、占位符替换或新模板语言。
- 不预置 `commit`、`review`、`test` 或任何其他具体 Skill，也不为任何 Skill 名称加入专用代码。
- 不自动执行目录型 Skill 中的脚本，不自动导入所有参考文档，也不允许 Skill 绕过已有安全边界。
- 不新增云同步、远程 Skill 存储、多用户共享、权限提升或模型自动降级策略。

## 验收标准

- AC1：在三个来源分别放置同名与不同名的有效 Skill 后，目录只显示每个名字的最高优先级版本，结果在重复运行中一致。
- AC2：某个 Skill frontmatter 或入口 Markdown 损坏时，目录中其他有效 Skill 仍可使用，诊断能指出被跳过的文件和原因。
- AC3：任一有效 Skill 的白名单声明不存在的普通工具时，ArtCode 启动失败并指出 Skill 来源和未知工具；不会进入交互会话。
- AC4：首次普通模型请求只包含 Skill 名称与一句说明，不包含任何完整 SOP；模型加载一个 Skill 后，下一次请求可观察到该完整 SOP。
- AC5：自然语言提出与目录说明相符的需求时，模型可以调用系统级加载能力；用户输入 `/<Skill 名>` 时，在同一轮完成加载和执行。
- AC6：激活多个 Skill 后，每次主请求、重建请求和重试请求都含全部激活 SOP；清空对话后 SOP 不再出现，工具集合恢复未激活状态。
- AC7：单个激活 Skill 时，模型只看见其白名单中的普通工具及系统级加载能力；多个激活 Skill 时，模型只看见白名单交集中的普通工具及系统级加载能力。
- AC8：Skill 白名单无法使模型绕过既有 Plan 限制、权限审批、路径政策、危险命令检查、沙箱或 MCP 审批。
- AC9：共享模式的过程和最终回复保留在主会话历史；独立模式仅带入声明数量的完整历史轮次，且完成后主历史只新增最终总结。
- AC10：指定专用模型的 Skill 只影响本次执行；模型不可用时产生明确失败，后续普通对话继续使用原会话模型。
- AC11：修改有效 Skill 后，下一次请求无需重启即可使用新内容；将已激活 Skill 改坏后，当前会话继续使用最后有效版本并显示诊断。
- AC12：目录型 Skill 的入口、模板、示例、辅助脚本和参考文档可作为一个能力包被发现；除入口 SOP 外，附属资源不会自动执行、不会自动全部注入，也不会被识别为其他 Skill。
- AC13：不使用任何 Skill 的普通对话、命令、Plan/Do、会话恢复、记忆、上下文压缩、MCP 与权限回归测试保持通过。
