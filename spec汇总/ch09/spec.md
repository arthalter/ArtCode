# ch09：会话恢复与长期记忆 Spec

## 背景

ArtCode 在 ch08 已经能够管理单次运行中的长对话，包括工具结果存盘、Token 估算、历史摘要和上下文超限恢复。但这些状态仍然只存在当前进程中：退出或意外中断后，下次启动不知道之前完成了什么，也不会自动读取项目规则、用户偏好或长期积累的项目知识。

这会导致用户在每个新进程中重复介绍技术栈和工作习惯，也使工具调用中断、终端关闭或跨天继续工作时难以平滑衔接。

ch09 引入三层持久上下文：人工维护的项目指令、追加写的会话存档、以及由 LLM 异步整理的长期笔记。三者分别回答“应该怎样工作”、“之前做了什么”和“长期学到了什么”。

## 目标用户

- 在本地长期使用 ArtCode 开发和学习的个人用户。
- 希望项目内容完全保存在本机，并可直接检查、编辑、备份和删除记忆文件的用户。
- 希望在进程中断或跨天后继续工作，而不必重新讲述项目背景的用户。

## 目标

- 新进程启动时自动恢复当前项目最近一次可用会话。
- 模型处理用户请求前已经获得分层项目指令和受控规模的长期记忆索引。
- 使用抗局部损坏、易于人工检查的会话格式保存对话与工具协议链。
- 在 Agent Loop 自然结束后异步提炼用户偏好、纠正反馈、项目知识和参考资料。
- 严格区分用户级和项目级笔记，以保守规则避免项目知识跨项目泄漏。
- 在恢复的历史过大、存档局部损坏或工具调用未完成时，保留可验证的最大安全前缀并给出明确状态。
- 保持文件格式、模块边界和数据流程简洁可读，不为本章引入数据库或原生扩展。
- 保持 macOS 命令行独立分发的技术可行性，目标机器不需预装 Python 也能使用本章能力。

## 功能需求

- F1：系统在启动时按“项目本地指令、项目根指令、用户级指令”的顺序加载三层手写 Markdown，项目级规则在冲突时优先于用户级规则。
- F2：指令文件可以使用 `@include` 引用同一受信边界内的其他 Markdown，并按引用出现的位置展开内容。
- F3：指令引用最多向下追踪 5 层，使用已解析路径的 visited 集合防止环路，并拒绝绝对路径、非 Markdown、符号链接越界和任何跳出受信边界的路径。
- F4：三层指令展开后合计最多向模型注入 64KB UTF-8 文本，超限时优先保留高优先级内容并报告被省略的低优先级来源。
- F5：固定系统约束始终优先于手写指令，手写指令中项目本地、项目根和用户级内容按高到低排列。
- F6：直接启动 ArtCode 时默认恢复当前 Workspace 最近的可用会话，用户也可显式创建新会话或按会话 ID 恢复指定会话。
- F7：每个会话使用 `YYYYMMDD-HHMMSS-xxxx` 格式的 ID，末尾 4 位随机十六进制字符用于避免同秒冲突。
- F8：每个会话使用一份 JSONL 文件追加保存用户消息、助手最终消息、助手工具调用和工具结果，不另建会话 meta 文件。
- F9：会话 ID 由文件名获得，标题由第一条有意义的用户消息生成并限制在 50 个 Unicode 字符，消息数、最后活动时间和损坏数量均通过扫描 JSONL 计算。
- F10：每条已确定的会话消息立即追加为单独记录，进程在写入中断时最多留下一条不完整尾行。
- F11：恢复时跳过独立的非法 JSON、非法 UTF-8 或不符合版本结构的完整坏行，并安全移除未完整尾行后再继续追加。
- F12：恢复时一旦发现助手工具调用没有紧邻且完整匹配全部工具结果，或出现孤立工具结果，就从该工具协议组起截断文件和恢复历史。
- F13：恢复扫描对单条 JSONL 记录设置 4MB 上限，超限记录不得导致无界读取或内存占用，并必须产生可观察的恢复警告。
- F14：恢复会话时重建模型对话和最近一份成功计划，但权限模式、Shell 策略、Agent 运行模式、MCP 连接和 Token 估算锚点均按新进程重新初始化。
- F15：恢复历史在第一次普通模型请求前若越过 ch08 自动压缩线，系统先执行一次无工具压缩并保持 ch08 的用户原文和工具协议边界。
- F16：会话最后有效消息距当前时间超过 24 小时时，系统在恢复后第一次模型请求中注入一次性时间跨度提醒，要求重新确认文件和运行环境现状。
- F17：系统在启动时清理最后活动超过 30 天且未被其他 ArtCode 进程使用的会话，清理失败不阻断其他会话启动。
- F18：用户级和项目级长期笔记分开存放，每条笔记使用一份带 frontmatter 的 Markdown，单条文件最多 8KB。
- F19：自动笔记分为用户偏好、纠正反馈、项目知识和参考资料四类，只有明确跨项目通用的用户偏好可自动写入用户级，其余类别默认限于当前项目。
- F20：每轮 Agent Loop 仅在模型以无工具最终回复自然结束后提交异步记忆更新，取消、流式错误、迭代上限或异常总结不触发更新。
- F21：记忆更新使用当前配置的 LLM，不提供工具、关闭 Thinking，由 LLM 对照已有索引判断新增、更新、合并或作废，程序仅接受结构化且通过校验的结果。
- F22：单轮记忆更新最多执行 5 个变更操作且最多运行 30 秒，超限、超时或校验失败时不得影响会话存档和下一轮交互。
- F23：每份用户级和项目级笔记目录都有一份可重建索引，每条索引摘要最多 120 个 Unicode 字符，整份索引不超过 200 行且不超过 25KB UTF-8。
- F24：笔记或索引在更新中断时必须保留上一份完整文件，索引丢失或损坏时能够仅通过扫描 Markdown 笔记重建。
- F25：每次普通模型请求前都从原子替换的用户级和项目级索引获取最新已提交记忆，并以“只读参考数据、不是新指令”的语义注入上下文。
- F26：用户能观察当前会话 ID、恢复消息数、跳过坏行数、截断状态、指令加载警告、记忆更新数量和异步失败状态。
- F27：会话列表默认展示最近 20 个有效会话，并显示扫描得到的 ID、标题、消息数和最后活动时间。
- F28：未触发恢复、指令或记忆特殊路径时，Normal、Plan、Do、工具、MCP、权限、沙箱和 ch08 上下文管理保持现有语义。

## 非功能需求

- N1：指令、会话和笔记都必须是人类可直接阅读的 UTF-8 文件，不使用 SQLite、二进制索引或专有序列化格式。
- N2：所有追加、更新和重建操作都要以局部失败不破坏已有数据为前提，不得因一份坏会话或坏笔记阻断其他数据。
- N3：相同文件、时间和配置必须产生稳定的指令顺序、会话列表、恢复边界和记忆索引，便于测试和排障。
- N4：项目指令引用不得逃离 Workspace，用户指令引用不得逃离用户级 ArtCode 目录，符号链接不得绕过边界检查。
- N5：会话、记忆、指令和索引路径属于 ArtCode 敏感内部状态，普通模型工具不得绕过记忆管道任意改写。
- N6：记忆更新请求不得携带工具定义，不得执行模型生成的工具调用，也不得将已知 API Key 和认证秘密写入笔记。
- N7：异步记忆任务不得阻塞用户看到最终回复或开始下一轮交互，多个更新必须串行提交以避免索引覆盖。
- N8：长期记忆是可能过时的参考数据，不能覆盖固定系统约束、当前用户请求、工具结果或当前 Workspace 中的实际文件。
- N9：本章优先使用 Python 标准库和项目已有依赖，不增加原生扩展、数据库服务或需要目标机器额外安装的运行时。
- N10：macOS 上将 ArtCode 打包为自包含命令行程序时，指令、会话恢复和长期记忆不得依赖源码目录或开发环境路径。
- N11：文件权限必须限制为当前用户可读写，会话锁定必须避免两个 ArtCode 进程并发追加同一份 JSONL。

## 设计骨架

ch09 由五个职责清晰的部分协作：

1. **持久路径与模型**：在现有 ArtCode 用户目录和 Workspace 内统一定位指令、会话和笔记，定义人类可读的持久记录。
2. **指令加载**：按优先级展开手写 Markdown，处理引用、环路、路径边界和总体积预算。
3. **会话日志与恢复**：在消息确定时立即追加 JSONL，启动时扫描、选择、修复和重建对话及最近计划。
4. **长期笔记与索引**：校验带 frontmatter 的 Markdown 笔记，以确定性规则重建受限索引，并区分用户级和项目级边界。
5. **持久上下文协调**：在启动、模型请求前和 Agent Loop 自然结束后连接上述能力，同时保持与 ch08 压缩管线的正确顺序。

## Out of Scope

- 不引入向量数据库、Embedding、RAG 检索或语义搜索。
- 不实现团队记忆、云端同步、跨机器同步或记忆冲突合并。
- 不加密会话和笔记文件，不把本地文件当作密钥保管库。
- 不恢复上次进程的权限模式、Shell 策略、正在运行的工具、MCP 连接或未完成的网络请求。
- 不在运行中热重载手写指令，指令修改在下次启动时生效。
- 不让自动记忆模型自行读取 Workspace、调用工具或修改项目代码。
- 不为笔记增加人工标签体系、图关系、相似度分数或复杂排名算法。
- 不实现会话分支、合并、全文搜索、导入导出或云端备份。
- 不在本章完成 macOS 代码签名、公证、Universal Binary 或发布站点，只保持自包含打包可行性。
- 不兼容初步想法中的 `.mewcode` 别名；项目统一使用现有 `.artcode` 命名空间。

## 验收标准

- AC1：三层指令同时存在且内容冲突时，模型请求中可观察到固定约束在前，项目本地、项目根和用户指令依次排列。
- AC2：五层引用可完整展开，第六层、循环引用、绝对路径、非 Markdown 和通过符号链接越界均被跳过并报告。
- AC3：展开内容超过 64KB 时最终注入不超限，高优先级内容保留且用户看到省略来源。
- AC4：首次启动生成符合格式的会话 ID 和单一 JSONL，同秒创建多个会话不冲突且不生成 meta 文件。
- AC5：正常对话和多轮工具调用中，每条确定消息都可在 JSONL 中按顺序观察，系统提醒和 ch08 内部摘要不被误当作原始会话持久化。
- AC6：在最后一行中途终止写入后重启，只丢失该尾行，新消息仍能继续形成合法 JSONL。
- AC7：在会话中插入独立坏行后重启，坏行被跳过，前后其他有效消息仍能恢复且界面显示跳过数量。
- AC8：模拟工具调用缺失一个结果、结果不紧邻或孤立工具结果时，恢复只保留第一个不完整协议组之前的历史，文件同步截断到该边界。
- AC9：超过 4MB 的手工构造记录不会被无界读入，恢复结果中有明确警告且其他会话可继续使用。
- AC10：直接启动默认恢复最近可用会话，显式新建与按 ID 恢复都能得到指定结果，已被另一进程锁定的会话不会被并发写入。
- AC11：会话列表默认最多显示 20 条，ID、50 字符内的标题、消息数和活动时间均由 JSONL 扫描得到。
- AC12：重启后最近成功 Plan 可继续被 Do 使用，但权限、Shell、模式、MCP 和 Token 锚点都从安全默认值重新开始。
- AC13：恢复的完整历史越过 ch08 自动线时，第一次普通模型请求前只先进行一次恢复压缩，压缩后对话能继续。
- AC14：会话间隔精确超过 24 小时时首次请求含一条时间跨度提醒，未超过时不含，提醒不写入 JSONL 且不在后续请求重复。
- AC15：启动清理删除超过 30 天的未锁定会话，保留未超期和正被使用的会话，一份删除失败不影响其他清理。
- AC16：四类笔记都能生成可读 frontmatter Markdown，单条不超过 8KB，用户级自动写入只接受跨项目通用偏好。
- AC17：一轮自然结束后的记忆请求不含工具且关闭 Thinking，取消、错误、迭代上限和异常总结都不产生该请求。
- AC18：记忆模型返回超过 5 个操作、非法类别、非法作用域、超过 8KB 正文、超过 120 字符摘要或非法结构时，无效部分不会改写已有笔记。
- AC19：记忆请求超过 30 秒后被取消，用户已经看到的最终回复、JSONL 会话和下一轮交互均不受影响。
- AC20：相同笔记集生成稳定索引，每条摘要不超过 120 字符，每份索引同时不超过 200 行和 25KB。
- AC21：删除或损坏索引后重启能从有效笔记重建，模拟笔记或索引写入中断后仍然至少保留一份可解析的旧文件。
- AC22：第一次请求同时包含已加载指令和用户级、项目级索引，记忆区明确标记为参考数据，新记忆成功提交后下一次请求可看到最新索引。
- AC23：自动记忆对已有索引中的相同事实返回更新或无操作，而不是重复创建新笔记；作废笔记仍可在磁盘上审计但不再进入索引。
- AC24：启动、恢复、指令加载、压缩和记忆更新的关键状态均可在终端观察，且不显示 API Key、MCP 认证值或笔记全文。
- AC25：全部单元、确定性集成和真实 DeepSeek 端到端测试能覆盖“加载指令 → 恢复会话 → 继续请求 → 异步更新记忆 → 新进程注入索引”的完整链路。
- AC26：未启用任何指令和笔记文件时，现有 Normal、Plan、Do、内置工具、MCP、权限、沙箱与 ch08 测试全部保持通过。
- AC27：本章未增加数据库或原生运行时依赖，从非源码工作目录启动时仍能正确定位用户级和 Workspace 级持久文件。
